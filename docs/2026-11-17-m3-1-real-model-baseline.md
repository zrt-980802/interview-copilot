# M3-1 真实模型基线与事实边界修正

日期：2026-11-17
状态：完成首轮真实接口验证、Prompt 修正和请求契约回归；M3 回答质量验收未通过，整体产品未验收。

## 验证范围

使用用户授权提供的接口 `https://new-api.carobo.cn/v1`，完成一次模型列表读取和 10 次鉴权聊天请求。仅发送脚本内的合成练习项目材料，没有读取个人 `config.json`、`.env`、简历或历史正文。密钥通过子进程 stdin 传递，仅在测试进程内使用；未写入源码、配置、日志或本报告，也没有为日常服务持久化配置。

模型列表包含 `deepseek-v4-flash-0731`、`deepseek-v4.1-flash`、`deepseek-v4.1-flash-1017`、`qwen3.8-max`。聊天测试仅覆盖 `deepseek-v4.1-flash` 和 `qwen3.8-max`。

固定合成背景：Python/PostgreSQL 练习订单查询接口，角色是接口开发，未承担负责人职责，没有生产压测、量化指标或论文。固定问题包括缓存一致性原理、带错误经历前提的性能优化问题，以及缓存并发风险深挖。

常规请求统一使用 temperature `0.4`、max_tokens `1200`、45 秒本地截止时间。协议诊断使用“只回复 OK”的最小请求、64 tokens 和 25 秒截止时间，不与完整回答比较速度。脱敏输出和中间失败样本全部保留在 [验证记录](evidence/2026-11-17-live-model-smoke.json)。

## 已确认的问题与修改

旧 Prompt 在材料明确“没有压测和量化指标”的情况下，仍把 `order_id` 查询计划从 Seq Scan 改为 Index Scan、增加复合索引等通用优化写成已实施经历。原理题也把假设实现写成“我用”的方案，并把 TTL 描述成无条件的脏数据存活上限。

本轮修改 `copilot/llm.py`：

- 简历、论文、JD、真实发言和外部补充以 user JSON 数据传入；控制指令保留在 system 消息。模型仍可能错误理解资料中的指令，这不是防注入的完备保证。
- 分开表示本人实际发言、历史 AI 输出和快速卡建议，深挖不再假定快速卡已由本人说出口。
- 去掉强制逐条举个人例子、特定论文别名，以及将外部参考转成个人经历的要求；资料不足时区分实际经历与待验证方案。
- 明确角色、动作、指标和结果需要材料支持；严格保证需交代条件，同一答案的结论与反例需相容。
- 保留快速卡行式协议和深挖 Markdown，取消机械的 120 字历史截断及深挖 260 字限制；尚未实现统一上下文预算。

增加 `scripts/probe_live_model.py`：显式指定端点、模型、案例和限额，使用实际 `LLMClient.stream_quick/stream_detail`；提供最小协议诊断，输出耗时、状态、答案与当前 Prompt 的 SHA-256。截止时间通过现有取消令牌中断本地请求，不代表供应商停止计算或计费。

## 未通过项

以下依据本轮保留的输出，不因请求成功而视为通过：

1. DeepSeek 深挖仍宣称“上界是 TTL 加补偿延迟”。TTL 从一次具体写入开始计时，延迟旧读回填、反复重填、无界请求或补偿时延都会破坏从数据库提交开始计算的统一上界；必须明确这些条件。
2. 深挖把 single-flight 读合并列为接近强一致的手段。合并读请求不等于协调写入和回填，不能据此推出读写一致性。
3. 版本号/CAS 方案没有说明删除后版本如何保留、比较操作的原子性，以及主从延迟等前提。当前原理题也有过度概括和不清楚的因果表达。
4. 当前经历题推断了“没有线上流量”，材料只明确练习项目、没有生产压测和指标。缺少信息不能自动变成否定事实，事实约束还需覆盖这类推断。
5. 当前快速回答为 462、673、536 字，深挖 847 字，仍偏长。应结合评测及新界面的扫描体验收敛，不能靠强行截断隐藏未完成答案。

经历题没有重复旧样本中的索引改造、执行计划变化或量化成果编造，表明这项策略有改善；单个同题复测不能证明已消除幻觉。没有旧版深挖对照，不对其作提升结论。
