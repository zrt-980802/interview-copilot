# 历史复盘与来源保存

在电脑工作区点击历史图标，或访问电脑管理入口的 `/history`。列表可按会话标题、问题、回答和深挖正文搜索；搜索中的 `%`、`_` 按普通字符处理。每页 30 条，可继续加载。空会话保留在数据库中，但不占历史列表。

选择会话可阅读问题、回答、当时的本人发言和已经生成的深挖。回答来源可展开查看当时发送给模型的摘录；复制按钮复制原回答文本，下载按钮导出 Markdown，包含原文、来源和模型信息。刷新保留所选会话，窄屏返回按钮切回列表。读取失败可刷新重试。历史页面只用于回看，不会启动采集或生成新的深挖。

## 保存语义

- 完成回答时，原文、Answer Document v1、实际上下文来源、任务标识、模型和尝试次数在同一数据库事务中保存。回答不再按 4000 字截断。
- 服务重启后读取保存的来源，不重新读取当前简历或笔记来拼接历史依据。修改源文件不会改变过去的来源摘录。
- 取消或失败的半截回答仍由当前会话快照显示，本阶段不新增这类草稿的跨重启持久化，也不保存每次失败尝试的完整输出。
- 旧记录显示“原始记录”。缺失或损坏的文档不影响原文阅读；损坏时显示“来源记录不可用”。旧版本已截断的正文和未记录的来源无法恢复。
- 磁盘上的渲染 HTML 不直接使用；读取时校验来源结构，并从原文重新生成禁用原始 HTML、图片的 Markdown。来源匹配不等于技术结论或个人经历已通过核实。

只有电脑管理入口提供历史。手机显示端没有 `/history`、历史 API 或相应静态资源，即使配对成功也不能浏览历史库。

## 数据升级与回退

正常数据路径仍为项目内 `data/history.db`。若启动时发现旧 `turns` 表且尚无 `answer_documents`，使用 SQLite backup API 在同目录生成一次一致性副本：

```text
data/history.pre-documents-v1-<日期时间>-<随机标识>.db
```

备份包含 SQLite 已提交状态及 WAL 中的已提交数据。备份成功后新增 `answer_documents` 表；旧 `sessions / turns / details / events` 的结构和记录不变。新库无需旧库备份。正常再次启动不会重复生成升级备份；启动或写入失败会反馈存储错误，历史 API 返回 503，不把错误作为空列表。

备份、数据库和导出均可能含个人材料摘录，按本地私有数据保存。`data/` 已在忽略列表中。本阶段只在临时数据库验证升级；没有启动真实配置、升级个人数据库或读取个人历史。

回退应用代码时，旧代码可继续读取原有表，多余的新表无需删除。需要恢复升级前数据时，先完全停止所有相关服务，保留当前数据库及同名 WAL/SHM 的独立副本，再将升级备份恢复到独立目录验证，最后切换到恢复后的数据库。不要将旧 `.db` 与另一个版本的 WAL/SHM 混用。恢复升级前备份会丢失备份之后的记录；单纯回退代码不需要恢复旧数据库。

导出直接作为下载响应发送，不写服务端临时 Markdown，不返回磁盘路径。历史页面和 API 响应设置 `Cache-Control: no-store`。
