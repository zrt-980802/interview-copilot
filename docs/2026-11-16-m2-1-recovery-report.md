# M2-1 会话快照与事件恢复

日期：2026-11-16
状态：已实现并通过离线 HTTP/SSE 与浏览器回归；整个 M2 尚未完成。

## 使用行为

- 页面刷新、新窗口打开时恢复当前服务进程内已接收的题目、快速答案和深挖内容，包括生成中的部分文本。
- 原生 EventSource 断线重连时携带 `Last-Event-ID`，在保留范围内补发缺失事件；补发后继续接收同一条事件流。
- 游标失效、超出保留范围、来自旧服务进程，或连接积压超过限制时，改用最新会话快照恢复。
- 页面按事件编号去重。发现编号缺口时重新连接取得快照；旧连接的迟到回调不能覆盖新连接状态。
- 已完成、生成中、失败和取消的回答分别恢复；深挖仍归属原始题目，失败后可重试，生成中的方向保持禁用。
- 页面恢复不重新提交问题或深挖请求；迟到的清空 HTTP 响应不再将界面切回旧会话。

## 关键实现

`src/interview_copilot/services/event_stream.py` 提供无导入副作用的 `ReplayEventHub`。发布顺序由锁保护，事件采用不可变 JSON 记录，不持有可被调用方继续修改的 payload 引用。

| 约定 | 实现 |
| --- | --- |
| 事件编号 | `<服务进程随机标识>:<单调序号>`，同时出现在 SSE `id` 和 JSON `event_id` |
| 发布元数据 | JSON 事件增加 UTC `created_at`，保留当前入口既有的 type 和归属字段 |
| 回放缓冲 | 最多 2048 个事件且最多 4 MiB JSON 正文，先达到的限制生效 |
| 单连接待发送缓冲 | 最多 256 个事件且最多 512 KiB JSON 正文；超限明确触发快照恢复 |
| 首次连接 | 在统一发布锁内完成订阅和状态捕获，先发 `session_snapshot`，再发同步标记 `stream_ready` |
| 有效游标重连 | 同一边界内取得待补发事件及实时订阅，补发后发送 `stream_ready` |
| 连接积压 | 清理该连接的旧积压，原子捕获最新快照，恢复后接收后续新事件；其他连接继续工作 |
| 连接回收 | 断开、生成器关闭和初始快照失败均释放订阅；阻塞读取会被唤醒 |

`SessionManager` 新增流式内容保留与不可变 `AnswerSnapshot`。这些内容不会作为已完成的候选人回答进入生成历史。快照包含任务 ID、类型、方向、正文、状态和错误，并保留每道题目的 generation 和时间。

当前入口新增 `GET /api/session/snapshot`，SSE 继续使用 `GET /api/events`；两者返回 `Cache-Control: no-store`，SSE 另设置 `X-Accel-Buffering: no`。问答状态变更、事件发布、订阅边界及快照捕获使用同一把应用锁，避免状态已经更新而游标尚未对应的间隙。

前端在收到快照或完成补发后显示“已连接”，连接已建立但尚在补发时显示“同步中”。快照重建期间暂时关闭组件滚动，保留同一会话回看时的滚动位置；整体自动跟随策略仍属于 M4。

## 验证边界与下一项

- 预览使用合成设备、材料、持久化和固定回答，不读取个人配置、简历或历史，不采集真实音频或调用真实模型。
- 重连测试通过预览专属 `POST /__regression__/disconnect` 结束 SSE 连接，触发浏览器的原生重连；这个路由只存在于测试预览，没有加入生产 `server.py`。没有进行真实 Wi-Fi 中断、手机锁屏或反向代理部署验收。
- 快照与补发缓冲位于当前服务内存，服务重启后使用新的事件标识和新会话；本批不恢复进程崩溃时的部分输出，也不从 SQLite 重建旧会话工作区。
- 快照包含核心题目与回答，不包含全部原始语音转写气泡和瞬时状态消息；这些消息只有仍处于补发范围时才回放。既有近期口述浮条继续由 `/api/state` 更新。
- 字节上限指事件 JSON 正文的缓冲预算，不是整个进程的内存上限；当前会话题目数、客户端数量和完整快照大小尚未设置总量上限。
- 当前入口仍使用原有扁平事件协议。本批没有宣称已完成旧迁移计划中的统一 envelope、生命周期或 Repository 验收。
- 下一项是资源生命周期与持久化关闭：消除当前入口导入时的启动工作，集中装配设备和 client，退出时取消任务、停止采集并 flush/关闭历史 writer。模型尝试边界、主动 HTTP 取消和超时仍待后续完成。
- 旧页面自动开启监听的行为、整体界面改版、回答质量和手机配对入口本批未改动；手机端口仍未开放。
