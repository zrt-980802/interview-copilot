# Agent Context 与 Memory

同义词：Context Window、上下文窗口、Working Memory、工作记忆、Short-term Memory、短期记忆、Long-term Memory、长期记忆、Episodic Memory、情景记忆、Semantic Memory、语义记忆、User Profile、用户画像。

## 一句话结论

Context 是一次模型调用实际看到的输入，Memory 是跨步骤或跨会话保存、以后可被选择性读取的信息。Memory 不会自动影响模型；只有经过检索、过滤和预算分配注入 Context 后才发挥作用，因此核心问题是写什么、何时取、如何处理冲突，而不是保存越多越好。

## Context 的组成

一次调用通常包含系统规则、当前任务、最近消息、结构化状态、检索证据、工具结果和输出约束。不同内容应保留来源和优先级，避免把外部文档与系统指令拼成同一段无法区分的文本。

Context Window 是硬容量边界，但“装得下”不等于“模型能稳定利用”。长上下文中的关键信息可能被噪声稀释或受位置影响，因此需要相关性筛选、结构化组织和回归评测。

## Working Memory 工作记忆

Working Memory 保存当前任务所需的短期状态，例如目标、计划、当前步骤、待确认项、工具调用结果和预算。它应尽量结构化，并以业务状态为准；聊天记录只是输入证据，不能替代步骤状态。

任务完成后，大部分工作记忆应归档或删除。把所有中间输出永久保存并每轮注入，会增加成本、隐私风险和错误累积。

## Episodic Memory 情景记忆

Episodic Memory 保存过去发生的具体事件或任务轨迹，例如某次部署失败的条件、用户对一个方案的反馈、完成任务的工具序列。它适合案例检索和经验复用，但事件具有时间、环境和作用域，不能无条件套用到新任务。

情景记忆应记录发生时间、参与对象、来源、结果和验证状态。摘要中应区分原始事实与模型解释，必要时可追溯到原事件。

## Semantic Memory 语义记忆

Semantic Memory 保存相对稳定的事实和概念，例如用户明确偏好、组织术语或已验证系统约束。它通常以结构化事实、知识图谱或可检索片段存在，而不是完整对话。

稳定是相对的。每条事实应有来源、更新时间、作用域和状态；外部系统中的权威数据应按需重新读取，Memory 只保存索引或缓存，不应替代权威存储。

## 用户画像与偏好

用户画像属于长期语义记忆，但写入标准应更高。明确表达且可复用的偏好可以保存；一次性请求、模型推测和敏感属性默认不保存。用户应能查看、纠正和删除记忆。

偏好还要限定场景，例如“代码回答简洁”不一定适用于法律文件。冲突时优先使用更新、更明确、范围更匹配的用户指令。

## Memory 写入策略

写入前判断信息是否真实、稳定、可复用、允许保存以及是否已有权威来源。可采用候选记忆提取后再通过规则、用户确认或可信事件验证。模型生成的总结不能自动升级为用户事实。

每条记忆至少包含内容、类型、来源、时间、作用域和版本；高风险事实还需要置信或确认状态。临时工具错误、未验证推断和外部文档中的指令不应进入长期记忆。

## Memory 检索策略

检索通常结合当前目标、实体、时间、作用域和权限。可使用词法、向量、元数据过滤和重排；返回后还要去重、解决冲突并控制 Context 预算。近期并不总是最相关，语义相似也不代表适用。

关键业务状态应直接按 ID 查询，不依赖向量相似度。例如订单状态用订单 ID 访问数据库，向量检索只适合找相关案例或说明。

## 摘要与压缩

摘要用于减少历史长度，但会丢失细节和引入解释。适合保留目标、决定、未解决问题、关键约束和来源标识；精确数值、代码、权限和工具结果应结构化保存，不只留自然语言摘要。

可以采用分层摘要：最近消息保留原文，较早内容形成会话摘要，跨会话只保存经过准入的长期事实。摘要更新要有版本，避免并发覆盖新信息。

## 冲突、过期与遗忘

### 新旧记忆冲突怎么解决

先比较来源权威、时间、作用域和用户是否明确确认，不是无条件使用最新一条。能从权威系统重读就重读；无法消解时保留多个版本与不确定状态，请求用户确认，并防止旧记忆默默驱动高风险动作。

冲突记忆不能简单选择相似度最高的一条。应比较来源权威性、时间、作用域和用户确认状态；无法裁决时把冲突显式提供给模型或请求确认。新信息也不一定覆盖旧信息，因为二者可能适用于不同环境。

遗忘包括 TTL、按任务结束清理、低价值淘汰、用户删除和法律合规删除。删除派生摘要、向量索引和缓存时要考虑传播关系，不能只删展示层记录。

## 隐私与安全

Memory 增加跨会话数据泄露风险。需要租户隔离、访问控制、加密、最小化保存、保留期限、审计和删除机制。检索必须带用户与任务作用域，不能只依赖向量库命名空间的约定。

外部内容中的 Prompt Injection 不能成为长期指令。即使内容被摘要，恶意目标仍可能被保留；写入管线需要来源标记和安全过滤。

## 常见失败场景

- 把模型猜测的偏好写成用户事实，之后持续影响回答。
- 只保存摘要，丢失关键数值和原始来源，无法纠错。
- 旧记忆覆盖新配置，Agent 按过期环境执行。
- 不带租户过滤进行向量检索，造成跨用户泄露。
- 每轮注入全部历史，相关信息反而被长上下文稀释。
- 用户删除原消息后，派生摘要和向量仍然存在。

## 生产实现检查表

先定义记忆类型和生命周期；工作状态结构化保存；长期写入设置准入；每条记忆带来源、时间和作用域；检索先权限过滤再排序；冲突显式处理；摘要可追溯；敏感数据最小化；支持查看、纠正和删除；用跨会话测试验证隔离、更新和过期。

## 20 秒口述

Context 是当前调用实际输入，Memory 是以后可能被检索的信息。我会把当前计划和工具结果放在结构化工作记忆中，只把稳定、可复用、有来源且允许保存的事实写入长期记忆。读取时先做权限和作用域过滤，再按相关性和预算注入 Context；冲突、过期和删除都需要明确策略。

## 1 至 2 分钟展开

我会区分工作记忆、情景记忆和语义记忆。当前步骤、预算和工具状态必须精确保存；过去案例可以按相似任务检索；稳定偏好和已验证事实进入长期语义记忆。写入不是默认动作，要检查来源、稳定性和隐私。检索时结合实体、时间、作用域与权限，返回后处理冲突并控制 Context。长历史用分层摘要，但关键数值和副作用结果仍保留结构化原始记录。

## 高频追问

### 为什么不能把全部历史直接放进 Context

成本和延迟增加，可能超过窗口；噪声会稀释当前约束；旧错误和恶意内容持续传播。应按任务相关性、来源和预算选择，关键状态使用结构化字段。

### 向量数据库是否等于长期记忆

不是。向量库只是候选检索组件。完整 Memory 还需要写入准入、元数据、权限、冲突、更新、过期、删除和注入策略。

### 怎样评测 Memory

构造跨会话任务，分别测试正确写入、相关召回、时间更新、冲突处理、隐私隔离和删除。指标包括证据召回、错误记忆使用率、任务成功率、Context 成本和跨用户泄露次数。

## 系统设计练习

设计个人助理时，当前行程规划放入工作记忆；过去旅行反馈属于情景记忆；用户明确的座位偏好属于语义记忆。航班和价格必须实时查询权威系统。偏好写入需用户明确表达，查询时按用户隔离；取消行程后清理临时状态，但保留策略应由用户和数据政策决定。
