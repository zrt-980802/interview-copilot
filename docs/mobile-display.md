# 电脑采集与手机显示

当前为开发版。电脑负责系统回环、麦克风、STT、回答与历史保存，手机只显示同一服务进程内的当前会话。手机不申请麦克风、摄像头或桌面权限。显示位置不会改变会议软件的摄像头、共享范围或进程可见性。

## 启动

升级既有虚拟环境的项目依赖，不覆盖本地私有配置：

```powershell
.\venv\Scripts\python.exe -m pip install -e '.[audio,pdf]'
```

- `start-desktop.bat`：检查服务身份与就绪状态，再打开电脑工作区；页面打开本身不会录音。
- `start-phone.bat`：开启独立手机端口，启动电脑默认系统回环和麦克风；不打开电脑浏览器。启动器输出局域网地址和短时配对码，随后关闭启动器不影响采集。
- 两个入口都读取 `config.json` 的电脑端口。已有服务未开启手机端口时，手机启动器明确报错，不强制重启进行中的会话。

也可以在终端启动，Ctrl+C 关闭时会执行同一份资源清理与历史 flush：

```powershell
.\venv\Scripts\python.exe server.py --mobile --auto-listen
```

`--mobile` 仅增加手机监听；`--auto-listen` 才会在服务启动后打开电脑两个采集通道。两者可单独使用。自动采集可选配置 `audio.loopback_device_index` 与 `audio.mic_device_index`，省略时使用系统默认设备。页面内临时选择的设备不会自动写回配置。

```json
{
  "port": 8527,
  "mobile": {"enabled": false, "host": "0.0.0.0", "port": 8528}
}
```

可用 `--port`、`--mobile-port`、`--mobile-host` 单次覆盖对应启动值。当前启动器固定管理入口到 `127.0.0.1`，不使用旧的 `host` 字段开放管理 API。两个端口会在装配运行时之前同时预占，任何一个占用都会明确失败。

## 耳机、扬声器与麦克风

工作区的“面试官 · 播放设备”选择会议软件实际播放声音的 Windows 输出端点，通过 WASAPI 回环读取该端点的数字音频；支持耳机、扬声器和可枚举的声卡，不依赖声音从电脑外放，也不通过本人麦克风收录面试官。

“我 · 麦克风输入”单独选择外部麦克风、耳机麦克风、麦克风阵列等输入设备，也可关闭。默认选项显示当前默认设备名称；采集中另显示实际使用的设备。页面刷新恢复正在采集的两路选择，运行中切换一路不会重启另一路。

默认设备使用当前 PortAudio 设备列表，不自动跟随 Windows 默认设备或会议软件的专用设备变更。Windows 默认设备变化后也应暂停并刷新设备，再启动采集。会议软件若单独指定耳机或麦克风，应在工作区选择相同端点。蓝牙设备在通话模式变化后可能出现不同端点，应以当前 Windows 可用设备为准。

插拔设备或设备端点发生变化时，先暂停采集，再点击“刷新设备”。服务会在两个通道都停止时重建 PortAudio 设备列表；同名同接口设备会重新匹配新编号，无法唯一匹配时回到该通道默认选项。刷新不会自动开始录音，手动选择也不会改写会议软件的设备设置。

## 配对与阅读

电脑工作区的手机图标打开配对面板。生成配对码后，选择可用局域网地址，用手机扫描二维码，或在该地址输入八位码。后台启动器也可直接给出地址和配对码，无需打开电脑页面。

配对码 120 秒有效，成功一次即失效；生成新码会替换旧码。二维码只携带短码 URL fragment，页面立即清除 fragment，并通过 JSON POST 兑换。已打开手机页面再扫码同样支持。长期凭据是随机生成的 HttpOnly、SameSite=Strict Cookie，服务仅在内存保存其哈希，不放入 URL 或浏览器 localStorage。

每台设备有最多 8 小时的查看权限，上限 8 台。每个来源地址一分钟最多 5 次兑换尝试，整体一分钟最多 30 次；刷新配对码、清空会话都不重置限流。新建/清空会话会保留已配对设备，自动转到新会话，清除手机上的旧题，但不会延长原授权到期时间；尚未兑换的旧配对码失效。刷新或关闭电脑网页、重新生成配对码不影响已配对手机。可在电脑撤销全部访问，或在手机退出配对。服务停止和重启仍会使旧授权与旧码失效。

手机显示当前题与分层回答，支持选择旧题、跟随最新、16-26px 字号、明暗切换和专注显示。深挖只显示电脑已生成的内容，手机不能发起深挖或提问。支持的浏览器可申请屏幕常亮；局域网 HTTP 上部分浏览器不提供该能力，按钮会禁用或显示失败提示。

事件流与快照共用现有会话标识和有界事件记录。手机刷新会恢复当前会话；断线、页面返回前台与网络恢复会重新同步；回看旧题时正常重连保留当前选择。整页刷新默认跟随最新题。新会话通过同一事件流通知手机重置显示并跟随最新题；断线期间切换会话也会在重连时恢复当前会话。撤销后，旧流在下一次读事件或空闲检查时关闭，手机清除已显示的回答。服务不能收回设备已经收到的内容或截图。

手机只接收正式题目、回答和简化采集状态；不接收完整简历、原始口述缓冲、设备列表、本机路径元数据、检索背景快照或管理日志。回答本身可以包含模型选用的材料摘录与引用文字，不能把这理解成会过滤掉回答正文中的所有敏感信息。

## 网络

第一版使用同一可互通局域网中的 HTTP，不提供传输加密或公网访问。指定 `mobile.host` 可只绑定某个局域网接口；默认绑定所有 IPv4 接口，地址候选排除回环、链路本地和公网地址，但不会自动判断路由、访客 Wi-Fi、热点隔离或虚拟网卡是否可从手机访问。

手机面板会区分正式局域网监听和仅绑定 `127.0.0.1` 的本机预览。模拟预览的 8542/8543 等回环地址无法被另一台手机访问；正式入口通常为电脑管理端口 8527 与独立手机端口 8528。多地址情况下优先显示当前出站路由使用的地址，其他候选仍可能属于虚拟网卡。

如果手机无法打开网页，先检查电脑 IP、端口是否监听、同网连接、访客网络隔离及 Windows 防火墙规则。主服务不会自动修改防火墙。需要放行时，先启动正式手机监听器，再以管理员 PowerShell 运行以下脚本，将示例地址替换为电脑当前活动物理网卡的 IPv4 地址：

```powershell
.\scripts\enable-phone-access.ps1 -LocalAddress 192.168.31.188 -Port 8528
# 删除同一网卡和端口的规则
.\scripts\enable-phone-access.ps1 -LocalAddress 192.168.31.188 -Port 8528 -Remove
```

脚本验证正式服务身份与端口归属，按真实监听进程的程序路径设置规则，限定所选物理网卡、单个本机地址、该地址的子网和单个 TCP 手机端口。规则使用当前 Windows 网络配置文件，不改变网络类别。DHCP 地址、网络类别或 Python 运行路径变化后需重新核对规则。执行结果写入被忽略的 `data/phone-access-result.json`。

手机端口没有电脑的上传、清空、历史导出、设备启动、配置修改等接口，也没有静态目录穿越或 OpenAPI 管理文档。配对、快照和事件都禁止跨站读取；敏感响应不缓存。

## 验证范围

自动测试使用合成材料、假音频引擎和假模型传输，通过两个真实 HTTP 监听器检查页面配对、同步、回看、刷新、模型尝试切换、取消、断线补发和撤销。浏览器窄屏模拟不能替代真实手机、实际锁屏、Wi-Fi 防火墙与 Windows 双通道采集验收。

2026-11-18 已在开发机启动正式局域网手机监听器，并通过系统管理员授权应用了限定子网的防火墙规则；电脑经自身局域网地址读取手机页面成功，未配对快照返回 401。已实际枚举耳机、扬声器与麦克风，未启动真实录音。真实手机 Wi-Fi、锁屏和跨设备同步仍待实机确认。完整设备/STT/LLM 自检与真实音频验收尚未完成，回答质量仍按 M3 遗留项继续处理。
