# M3-4 事实分栏与结构化答案展示

日期：2026-11-17

状态：答案结构、来源检查和当前页面展示已接通；M3 整体语义质量及 M4 全新工作区/手机端仍未完成。

## 本批实现

服务端生成统一的 Answer Document v1，包含结论、要点、材料摘录、待确认项、假设方案、验证计划、方向、来源和检查结果。保留原始流式字符串及历史写入，不要求模型先生成完整 JSON。未识别的行、后续解释、代码围栏里的协议标签和正文中的 `:::` 不再被丢弃。

经历题提示词增加明确的材料、待确认和假设分行约束；材料行需逐字摘录，服务端检查其是否出现在指定来源中。引用核对本次实际发送的来源与行号；代码里的引用符号作为字面代码。只校验摘录一致和定位范围，不把结果称为事实或技术正确性认证。

`on_context` 将经过输入预算后的来源绑定到具体任务，`answer_done.document` 与重连快照提供同一数据。过期来源回调会被拒绝，深挖旧题保留该题自己的材料。来源目前保存在内存，服务进程重启后历史数据库仅有原始回答，尚未完成 Repository 的来源持久化。

前端新增原生 ES Module `static/js/answer-content.js`。流式阶段立即显示草稿，完成后使用服务端文档；材料原文可展开，引用可点击定位对应片段，不匹配摘录保留并标为待核实。界面将“开口照说”改为“回答建议”，避免暗示模型输出已验证。没有方向行的完整回答也可继续深挖，本地澄清不提供无意义的完整版按钮。

回答区域改为无外框的段落层级，使用中性深色底与少量状态色。来源为可折叠的原文区，长文件名换行、代码在自身区域滚动。增加 Markdown 代码/列表/链接渲染，采用 CommonMark 库并禁用原始 HTML 与图片，未引入 CDN。模块加载失败时仍保留原文字，不显示空白卡。

本轮不是整体前端重做。原来的设备与采集工具栏仍在，桌面三栏工作区、材料准备面板和独立手机显示端留待 M4。

接口说明见 [Answer Document v1](answer-document-v1.md)。
