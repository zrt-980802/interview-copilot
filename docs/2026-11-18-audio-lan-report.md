# 耳机、麦克风与手机局域网入口修复

日期：2026-11-18。在此前未提交的 UI 改动上继续实施，未提交或推送本轮代码。

## 音频设备

- 面试官通道明确选择会议软件实际使用的播放设备，支持 WASAPI 回环可枚举的耳机、扬声器和声卡。本人麦克风是独立输入通道，不通过麦克风收录面试官的外放声音。
- 修正“扬声器（默认）”的误导名称，默认选项显示真实默认端点，采集中显示实际设备；输出通道增加选中值和实际编号的状态字段，页面刷新恢复两路选择。
- 麦克风默认设备优先使用 WASAPI 默认输入，与设备列表的优选接口一致；不可用时回退到普通默认输入。
- 增加暂停后“刷新设备”：在两路采集锁内检查都已停止，重建 PortAudio 后再枚举。刷新不启动录音，按名称与接口匹配变化后的编号，不能唯一匹配时回到默认选项。
- 切换一路不重启另一路；设备操作错误显示在采集区，刷新接口仅限本机管理入口，手机端不暴露该接口。
- 实际枚举开发机得到 Realtek 耳机、Realtek 扬声器、虚拟输出、外部麦克风与麦克风阵列；当前默认输出为 Realtek 耳机，默认输入为外部麦克风。

默认端点来自当前 PortAudio 设备列表，未实现运行中自动跟随会议软件或 Windows 默认端点变化；Windows 默认设备变化后也需暂停并刷新设备。设备检测成功不等于已完成真实声音采集验收。

## 局域网排查及处理

最初只有绑定 `127.0.0.1` 的 8542/8543 模拟预览，正式 8527/8528 没有监听。这是当时手机无法连接的直接原因；界面原先只显示“手机端口已开启”，也没有区别本机预览。

已完成：

1. 在本地私有配置中启用独立手机监听器，启动正式服务，未使用 `--auto-listen`，两路录音均关闭。
2. 实际确认电脑管理端为 `127.0.0.1:8527`，独立手机端为 `0.0.0.0:8528`。
3. 手机面板增加本机预览/局域网状态与端口；地址列表优先显示当前出站路由的网卡地址，避免把虚拟网卡排在前面。
4. 通过 Windows 管理员授权执行新增的 `scripts/enable-phone-access.ps1`，创建 `InterviewCopilot-Phone-8528-10` 规则。仅允许当前有线接口、本机 `192.168.31.188`、TCP 8528、远端 `192.168.31.0/24` 及真实监听程序。当前网络类别为 Public，规则匹配此类别，未修改网络类别或关闭防火墙。
5. 读取已生效规则核对范围。电脑通过 `http://192.168.31.188:8528/` 加载手机页面为 HTTP 200，未配对 `/api/snapshot` 为 401。正式电脑页面显示正确的耳机/麦克风默认名称、8528 已启用和优先局域网地址。

当前电脑入口：`http://127.0.0.1:8527/`。当前手机入口：`http://192.168.31.188:8528/`，需在电脑“手机显示”中生成配对码。

防火墙脚本检查服务身份与端口归属，使用实际监听进程的可执行文件，避免虚拟环境启动器与真正 Python 进程路径不一致。支持幂等更新与 `-Remove`，结果保留在被忽略的 `data/phone-access-result.json`。地址、网络类别或 Python 路径变化后需要重新核对规则。
