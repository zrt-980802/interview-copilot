# M4-3 多份参考资料的初始化与管理

日期：2026-11-17

用户确认范围是一份当前简历，加上面试过程中需要参考的多份资料、项目文档和 GitHub Markdown。实现围绕多份参考资料组织；没有将目标定义为多简历管理。

## 改动

- 新增 `services/documents.py`：独立 SQLite 清单、原文件归档、按内容去重、解析缓存、处理队列与初始化状态。处理顺序为保存、解析、概览、分块索引和就绪，失败可单独重试；原文件同名不覆盖。
- 初始化由已有 WorkerGroup 管理，单个初始化 worker 消费队列，不为每份文件创建不受限线程。退出时遵守现有取消/等待流程；中断的处理重启后重新排队，已就绪正文直接恢复 FTS 索引。
- 支持 PDF、DOCX、Markdown 和常见文本/代码文件。参考资料每批 20 份、每份 25 MB；PDF 页数、DOCX XML、总文本和队列分别设界限。扫描件/无正文返回可见错误。概览是正文节选，不是模型摘要或训练。
- 资料类型明确区分简历、本人项目、参考、论文和岗位。新简历每次一份，成功后替换当前背景，之前的原文件保留；参考资料默认 `reference`。启用/停用、分类调整与归档改变后续问题的检索范围，恢复归档保持停用。
- 新增 `services/remote_documents.py`：规范化具体公开 GitHub Markdown 链接，下载到本地后执行相同初始化，保存 raw URL 作为可追溯来源。仅固定 GitHub 主机，拒绝任意 URL、私有凭据和重定向，限制远程 5 MB 与整体 30 秒；遵循已有代理配置。
- `server.py` 接入运行时文件服务、批量上传、列表/预览、属性修改、归档、重试、原文件下载和 GitHub 导入。检索复用现有 BM25 索引和上下文预算，GitHub/参考材料不升级为个人经历。文档来源继续由 M4-2 保存到历史。
- `/files` 提供资料列表、搜索、状态筛选、初始化步骤、正文预览、类型/名称、启用开关、归档恢复、下载与 GitHub 导入。电脑工具栏跳转到新入口。窄屏使用列表/详情切换，轮询刷新不覆盖正在编辑的属性。
- 原有简历、论文和辅助资料保留在兼容区域，未自动搬迁或清理个人数据；其逐条迁移及范围管理尚未接入。新资料开关只控制新清单条目。手机不开放文件管理或下载。
