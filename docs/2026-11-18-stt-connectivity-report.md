# 本地 STT 502 修复

日期：2026-11-18。在此前 UI、设备与局域网改动上继续修复，未提交或推送。

## 原因

用户报告 `127.0.0.1:8760/v1/audio/transcriptions` 返回 502。检查当时 8760 无监听器，而旧 STT 客户端默认继承代理。相同 `/models` 请求在默认 httpx 配置下为 502，`trust_env=False` 时为连接失败，确认本机未启动的服务被 Windows 系统代理转换成网关错误。没有设置 HTTP_PROXY 等环境变量，也可能通过 Windows 系统代理触发此行为。

此前正式服务只启动了电脑及手机入口，未补启动外部 STT。原启动器又仅在主服务尚未运行且设置了 STT 目录环境变量时检查转写服务，已有主服务不会修复缺失的 STT。

## 修改

- 统一 STT 代理策略：回环地址与 localhost 直接连接，远端端点保留原策略；当前 `copilot/stt.py` 和 v2 STT provider 均应用。
- 当前客户端将本地连接失败显示为需要启动/检查 STT 服务，HTTP 错误只显示状态码和配置检查提示，不再把底层 HTTP 文档链接直接显示给用户。
- 启动器对本机服务请求显式禁用代理。无论主服务是否已运行，都检查本地 STT；支持配置 `stt.server_dir`，环境变量仍优先，使用配置 URL 的端口启动现有 `stt_server.py`。
- 记录 STT 后台日志，检测进程退出并等待 API 就绪。未就绪时电脑模式提示手动提问仍可用，手机模式拒绝自动采集。
- 本地私有配置填写了已有 STT 项目目录，没有修改外部 STT 源码或下载模型。

## 实际处理及验证

先暂停两路采集，避免继续丢弃失败片段。通过新启动器在主服务已运行的情况下成功补启动本地 STT，并用系统中文语音合成生成独立测试 WAV，直接请求真实 `large-v3-turbo`。

输入与识别内容一致：“这是一次本地语音转写测试，我们正在检查耳机和麦克风。”首次请求约 6.2 秒，只有标点差异。这是实际模型推理，测试不采集环境声音、不附带个人资料，也不调用回答模型。

随后向正式服务控制台发送 Ctrl+C，等待资源清理和端口关闭，通过新启动器平稳重启。最终监听：电脑 `127.0.0.1:8527`、手机 `0.0.0.0:8528`、STT `127.0.0.1:8760`；主服务 ready 且两路采集保持关闭。历史库保留，服务重启使原手机授权失效，需要重新配对。

- 聚焦 STT、provider、音频生命周期及旧客户端测试：**37 passed**。
- 最终 Python 全量：**342 passed**，仅既有 Starlette/httpx 弃用提示。
- 新回归使用真实本机 HTTP 服务及一个返回 502 的代理，分别验证当前/v2 客户端绕过代理；远端端点仍经过代理，验证连接错误信息。
- PowerShell 启动器语法检查通过；Windows PowerShell 5 实际执行了“主服务已运行、STT 缺失”的补启动和正常重启路径。

本轮没有重新执行浏览器全量，没有验证真实麦克风/回环到回答的全链路；前次 49 项浏览器结果不计作本轮重跑。真实合成语音识别成功不能替代会议现场噪声、分段和转写准确率测试。已跳过的失败片段没有恢复。
