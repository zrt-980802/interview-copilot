# 资料库

目标是一份当前简历，加上面试时可供参考的项目资料、论文、技术文档和 GitHub Markdown。资料初始化后按问题检索，不将所有文件全文堆入每次请求，也不把参考资料自动当成本人经历。

## 上传与初始化

电脑工作区的资料库图标打开 `/files`。选择资料类型后可批量上传参考文件，或通过“导入 GitHub”粘贴具体的公开 Markdown 文件链接。文件各自保存，原文件名相同也不会覆盖；相同内容的重复上传返回已有条目，类型不被新上传请求悄悄改变。

初始化依次完成原文件保存、正文解析、正文概览、按章节/行号分块和加入索引。页面显示等待、解析、索引、就绪或失败；失败文件可单独重试，不阻塞其他文件。概览为正文开头的节选，目前没有调用模型生成资料摘要、经历画像或训练模型。正文预览最多 16000 字，预览节选不等于索引只保留这些文字。

参考资料每批最多 20 份，单文件最多 25 MB。支持 PDF、DOCX、Markdown、TXT 和常见代码/配置文本。PDF 限 250 页，提取正文最多 200 万字符；扫描件不含可提取文字时提示先进行 OCR。Word 读取正文与表格文字，不运行宏或解压外部路径；暂不支持旧 `.doc` 文件。文本尝试 UTF-8/BOM，其次 GB18030，无法识别时显示失败。

原文、解析文本和清单存于 `data/documents/`，该目录受现有 `data/` 忽略规则保护。已就绪文件在重启后使用保存的正文恢复检索索引；初始化中断的文件重新排队。原文件、启用状态、分类、名称和归档状态持久保存。

## 类型与使用范围

- 简历：每次上传一份，作为当前候选人背景。新简历成功初始化后切换生效，失败时保留原有可用简历；旧副本留在资料库中，不覆盖原文件。
- 本人项目资料：由用户明确选择的本人经历材料，作为 `candidate_material`。该分类本身不是内容真实性认证。
- 参考资料：默认类型，包括普通技术文件和 GitHub 导入，作为 `reference`，不能自动成为“我做过”的经历。
- 论文：作为 `paper`，不因上传行为推断本人作者身份或实验成果。
- 岗位说明：作为 `job_description` 的可检索资料；本阶段未增加岗位配置与资料分组管理。

启用开关控制该文件是否进入后续问题的检索；初始化完成前不能手动启用。关闭不会回收已经发送给模型的内容，也不改变历史答案的来源快照。归档会停用文件并移到归档视图，原文件保留；恢复后需手动启用。可以修改资料名称和类型、查看正文、下载原文件。

旧版简历、论文和材料仍通过兼容链路加载，在“原有资料”区域列出。当前新资料的开关不控制这些旧条目，旧原文件和缓存没有自动搬迁或删除；旧资料的统一迁移与范围管理仍需后续接入。原有简历可以显式重新选用。

## GitHub Markdown

支持 `https://github.com/<owner>/<repo>/blob/<ref>/<path>.md` 和对应的 `raw.githubusercontent.com` 链接，也支持 `.markdown`。保留规范化的 raw 链接作为来源，下载正文进入同一初始化流程；后续引用能携带此链接和行号，并保存到历史来源快照。

仅访问固定的 GitHub raw 主机，不跟随重定向、不发送模型 API key 或仓库 token；查询参数与 fragment 不保存。单份远程 Markdown 最多 5 MB，整体请求最多 30 秒，网络失败会提示重试。遵循进程已有的代理/证书环境配置。私有仓库、目录链接、整库克隆和自动跟踪更新暂不支持。文件内容改变后需重新导入，旧快照保持原样。

## 验证范围

文件清单与初始化状态、重启恢复、失败重试、启用范围、来源类型、下载、GitHub URL/重定向/大小边界、桌面与窄屏操作均有自动回归。真实导入公开 pgvector README 并验证本地索引和回答来源快照；模型传输仍为合成预览，不代表新的回答质量验收。

电脑管理入口仅在回环访问，资料库拒绝跨站请求。手机端不能访问资料库页面、文件 API 或下载原文件。手机仍可能看到回答正文中的必要摘录。
