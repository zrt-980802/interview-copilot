# M2-3 模型尝试边界与主动取消

日期：2026-11-17
状态：已接入当前 HTTP、SSE、快照和页面，通过离线验证。整个 M2 尚未完成。

## 使用行为

- 主模型半途断流、请求超时、返回流错误、空答案或达到长度限制时，可以切换备用模型。每次尝试有独立编号和模型名称；切换时清除失败尝试的片段，最终显示和保存的完成答案仅来自成功的那一次尝试。
- 等待和生成中的快速卡、深挖卡提供方形停止图标，悬停或辅助技术可识别为“取消生成”。取消只作用于该任务，保留已经生成的部分文字并标记已取消。取消深挖后可以重试同一方向。
- 新问题替代旧快速回答、清空会话、关闭服务和手动取消，都会使对应模型请求的取消令牌生效。取消不会触发备用模型请求。
- 页面刷新和重连恢复尝试编号、模型名称、部分内容与取消状态；旧尝试的迟到事件不能写入新尝试。
- 所有通道失败时保留最后一次尝试的部分文字并显示失败原因。供应商异常正文不会直接出现在错误消息里。

## 实现

`copilot/llm.py` 保留同步业务接口，由现有模型工作线程调用。每次回答在自己的 asyncio loop 中创建并关闭 `httpx.AsyncClient`，使用 `Task.cancel` 中断等待响应头或读取中的请求。取消回调只向所属 loop 投递取消，不在会话锁内执行网络关闭或等待。

回答任务先关闭响应和客户端，再执行完成或失败回调。模型客户端关闭会停止接收请求、取消全部登记请求，并等待它们释放资源；超时会保留登记信息并抛错，后续可以重试清理。没有新增依赖。

`CancellationToken` 由 `SessionManager` 持有，按会话和任务隔离。取消快速回答同时使同题的预取增强任务失效。联网增强内部的请求仍受原有超时限制，本批没有把这些检索请求改为可即时中断。

| 约定 | 行为 |
| --- | --- |
| `answer_attempt` | 携带任务标识、正整数 `attempt` 和 `model`，同步重置服务端快照与前端正文 |
| `answer_delta` / `answer_done` / `answer_error` | 增加 `attempt`，前端只接受当前尝试的事件 |
| `answer_cancelled` | 指定被取消的任务，保留当前部分内容并移除其活动控制 |
| 会话快照 | 回答增加 `attempt`、`model`，保留既有内容与状态字段 |
| `POST /api/cancel` | 必须指定字符串 `session_id`、`task_id`；会话失效返回 409，参数无效返回 400，重复取消返回 `cancelled: false` |

协议处理接受 `[DONE]` 或明确的 `finish_reason: stop`，区分正常完成、空内容、异常 EOF、流内错误和截断。业务回调失败不会被当作模型失败而切换供应商。没有提供尝试重置回调的旧调用方，如果已经收到部分文字，失败后会收到错误并停止，避免把备用答案拼接到旧文字后面。

前端答案正文与控制区分开更新，流式刷新不会反复替换取消按钮。按钮尺寸固定为 28 x 28，完成、失败和取消后隐藏；取消操作不会停止音频采集。

## 边界与下一项

- 本批不需要 API key；没有读取个人配置、环境文件、简历或历史正文，没有采集真实音频或调用真实模型。真实回答质量对比阶段需要可用的接口地址、模型名称和本地配置的密钥，密钥不应发到聊天中。
- 客户端关闭连接不代表供应商已经停止计费或终止远端计算，具体取决于供应商实现。真实 TLS、代理和模型兼容性仍需后续验证。
- 部分失败或取消答案仍只保留在进程内快照，未增加历史表字段或进程崩溃恢复。数据库仅保存完成答案，原有正文截断策略保留。
- 本批未修改回答 Prompt，不能据此宣称答案变得更聪明；整体前端改版和手机配对监听仍未交付。
- M2 尚有 Repository 全面接入等工作。下一阶段建立合成回答评测样例，改善题意判断、证据边界、上下文组织和回答结构，再进行真实模型对比。
