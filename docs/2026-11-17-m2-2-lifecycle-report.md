# M2-2 服务生命周期与历史写入

日期：2026-11-17
状态：当前入口已接入显式启动、退出清理和历史 flush，通过离线回归。整个 M2 尚未完成。

## 本批完成

- 导入 `server`、`copilot.audio`、`copilot.llm`、`copilot.history` 时不读取个人配置、简历、历史或环境文件，不创建 HTTP 客户端、音频设备或后台线程。数据库会话也改到启动阶段建立。
- FastAPI lifespan 调用 `start_runtime` / `stop_runtime`，资源由 `app.state.runtime` 持有。保留当前入口的全局适配句柄，尚未完成所有业务接口到 v2 Repository 的迁移。
- 每次启动创建新的会话管理器、事件流、历史存储、模型客户端、双通道音频引擎和后台任务组；初始化中途失败时回收已创建的资源。拒绝同时进入两个 lifespan。
- 退出先停止任务接收，使回答任务与音频回调失效，撤销并等待问题合并计时器，断开 SSE；随后关闭音频和模型资源、等待后台任务，最后写入会话结束标记并关闭历史写线程。PortAudio 在创建它的线程内执行 terminate。
- 清理失败会继续尝试其他资源，返回异常并保留运行实例供重试；服务显示未就绪，不能用新实例覆盖仍未清理的旧资源。已注销的会话不会在重试时重复注销。
- 停止采集与最终关闭分开：暂停后允许重新开始，最终关闭才释放自有 STT 客户端、转写线程池和模拟音频源。注入的 STT 客户端由调用方负责关闭。仍存活的采集线程或转写任务不会被丢弃引用或报告为退出成功。
- 问题合并、模型生成、材料加载、热词延迟刷新和检索子任务均纳入退出处理。停止系统回环采集会撤销尚未成题的片段。
- `/api/start`、`/api/stop` 和论文重扫的阻塞操作移到工作线程，避免直接阻塞异步 HTTP 循环。

实际启动时仍兼容原配置路径和环境文件读取逻辑：配置在启动入口显式读取，原有环境文件加载只在创建生产模型客户端时调用。没有改变个人文件的存放位置。

## 历史存储

新增 `src/interview_copilot/services/history.py`，原 `copilot/history.py` 保留兼容转发接口。默认路径仍是项目 `data/history.db`，表和字段保持兼容，没有执行个人数据库迁移。

| 行为 | 当前保证 |
| --- | --- |
| 建立会话与题目 | 通过单写队列执行，事务提交后才确认并返回 ID |
| 会话归属 | 进入队列时确定 session ID，切换会话不改变已排队命令 |
| 事务失败 | 回滚批次，不返回未提交 ID；后续写入、flush、close 和健康状态暴露失败 |
| flush | 等待之前接受的写入完成提交，失败时抛错 |
| 正常 close | 关闭写入入口，按顺序排空队列，等待线程退出并关闭 SQLite 连接 |
| 队列满 | 原始状态事件允许丢弃但计数；核心命令明确拒绝并报告失败；数据库可写时仍提交此前接受的命令 |
| 读取 | 显式关闭读取连接，避免依赖垃圾回收 |

`GET /api/health` 返回服务标识、运行实例就绪状态、历史队列与错误统计、后台任务数量和清理错误类型。未启动、清理未完成或历史写入失败时返回 503。该接口不代表真实 STT、LLM 或音频设备已经通过可用性检测。

## 边界与下一项

- 没有读取个人配置、环境文件、简历或 `data` 正文，没有打开真实音频设备或调用真实模型。本批验证使用合成配置、模拟 HTTP transport、模拟设备与临时数据库。
- 关闭会等待组件完成或明确报告超时，不能强制结束任意 Python 线程。现有网络请求与子进程仍受各自超时限制；关闭 HTTP 客户端不等于所有阻塞请求已经即时中断。退出各阶段的超时不是整个服务的统一十秒上限。
- 正常退出的 flush 不等同于进程强杀或断电后的完整恢复。历史仍保留原来的 4000 字符截断策略，生成中的部分回答仍是进程内快照，没有增加崩溃后续写或自动恢复。
- 本批没有修改回答 Prompt，没有完成前端改版或手机配对监听，也没有进行真实 Wi-Fi、手机锁屏或音频质量验收。
- 下一项是 M2 的模型尝试边界与主动取消：处理主模型已经输出部分文本后切换备用模型的混流风险，并将取消传递到实际请求。之后继续回答评测与质量优化、前端和手机显示端。
