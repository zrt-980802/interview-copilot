# Agent RAG 与知识库

同义词：Retrieval-Augmented Generation、检索增强生成、Knowledge Base、知识库、Chunking、切块、Embedding、向量检索、BM25、Hybrid Search、混合检索、Rerank、重排、Grounding、事实落地、Citation、引用。

## 一句话结论

RAG 是在生成前从受控资料中检索证据并注入 Context，让回答基于可更新、可追溯的外部知识。完整 RAG 不只是向量数据库，而是文档处理、索引、查询理解、召回、重排、上下文组装、生成引用和分层评测组成的系统。

## RAG 解决什么问题

模型参数中的知识可能过期、缺少私有资料且无法给出可靠来源。RAG 允许知识独立更新，并让回答引用具体证据。它不能自动消除幻觉：检索可能失败，资料可能错误，模型也可能误读或忽略证据。

RAG 适合知识密集、资料会变化、需要引用或涉及私有文档的任务。纯创作、稳定常识或精确结构化查询可能更适合直接生成或数据库/API 工具。

## 数据摄取与解析

摄取阶段读取 PDF、网页、Markdown 或数据库记录，提取正文、标题、章节、表格和元数据，并去除导航、重复页眉等噪声。应保留来源、版本、时间、权限和原始位置，支持引用与更新。

解析质量决定后续上限。扫描 PDF 需要 OCR；复杂表格和代码不能只按普通文本处理；删除或更新源文件时要同步清理旧索引，防止不同版本同时命中。

## Chunking 切块

切块目标是让一个片段包含足够语义又不混入多个主题。常见策略包括固定长度加重叠、按标题和段落、按句子、按代码符号、按表格或语义边界。不存在对所有资料最优的固定块大小。

块过小会丢失上下文和限定条件；块过大降低检索精度并浪费 Context。可同时索引小块用于命中、返回父章节用于生成，或在命中后扩展邻近片段。选择必须用目标问题集评测。

## 词法检索 BM25

BM25 等词法方法依赖词项匹配，擅长专有名词、错误码、版本号、函数名和精确短语。它成本低、可解释，但对同义改写和跨语言表达能力较弱。

中文需要合适分词或 n-gram；技术词应保留英文、缩写和符号。领域同义词可以在查询或索引阶段扩展，但扩展过度会降低精度。

## 向量检索 Embedding

向量检索把查询和片段映射到表示空间，按相似度寻找语义相关内容，适合用户表达与文档措辞不同的场景。它仍受 Embedding 模型、语言、领域、块大小和距离阈值影响。

语义相似不等于事实支持。片段可能主题相关但无法证明具体结论；权限和时间过滤应在召回阶段明确执行，不能指望向量相似度处理。

## Hybrid Search 混合检索

混合检索并行使用词法与向量召回，再用加权分数或 Reciprocal Rank Fusion 合并。它通常兼顾精确术语与语义表达，但增加索引、延迟和调参复杂度。

是否采用混合检索取决于错误分布。如果失败主要来自专有名词，增加词法召回有价值；如果知识库很小且标题清晰，简单检索可能已经足够。必须对比基线而不是默认堆组件。

### 向量检索和 BM25 哪个更好

没有绝对更好。BM25 更适合精确术语、编号和专有名词，向量检索更适合同义表达和语义改写。工程上先建立可解释的词法基线，再根据漏召回类型决定是否加入向量和混合融合，并以真实问题集的 Recall@k、前几条精度、延迟和成本选择。

## Query Rewrite 与多查询

Query Rewrite 可以消解指代、补充领域术语或生成多个搜索角度。风险是改写改变原意，尤其是否定词、数字和实体。应保留原查询并把改写作为补充，关键约束结构化锁定。

多查询能提高召回，但会增加成本和重复片段。结果合并后需要去重和来源多样性控制，避免同一文档占满 Context。

## Rerank 重排

第一阶段召回追求不漏掉相关候选，重排阶段使用 Cross-Encoder、LLM 或规则对候选与问题的支持程度重新排序。重排可以提高前几条精度，但不能找回召回阶段完全遗漏的内容。

重排输入数量受延迟和成本限制。可先按权限、时间、文档类型过滤，再对少量候选重排；使用 LLM 重排时需评测稳定性和 Prompt Injection 风险。

## Context 组装

组装阶段按预算选择片段，保留标题、来源、位置和权限信息，处理重复与冲突。不要把文档内容放进系统指令；应明确标记为不可信参考数据。相关片段不足时应说明证据不足或回退到模型通用知识，取决于问题类型。

同一结论的相反资料需要同时呈现并标注版本或来源，不能由检索层静默选择。面试提词场景还应区分通用参考资料与候选人事实，通用知识不能证明个人经历。

## Grounded Generation 与引用

### 有引用为什么还可能是幻觉

引用存在只能证明答案链接了某个来源，不证明该片段支持对应 Claim。模型可能引错段落、忽略否定或时间限定、混合新旧版本，或在证据之外扩大结论。需要做 Claim-Evidence 对齐、蕴含和来源版本检查。

生成 Prompt 应要求基于证据回答、区分资料事实和推断，并使用给定来源标识。引用必须绑定实际提供给模型的片段，不能让模型自行编造文件名或行号。

引用存在不等于结论受支持。需要检查引用片段是否蕴含对应主张、是否遗漏限定条件。对于关键事实，可用规则或第二阶段验证器做 Claim-Evidence 对齐。

## 检索评测

### 如何分别评测召回和最终答案

召回层使用带相关文档标注的问题，看 Recall@k、MRR、nDCG 与无答案识别；固定召回片段后，答案层再评正确性、忠实度、完整性和引用支持。端到端评测两者都看，但不能仅凭最终失败猜是检索还是生成层。

检索层使用带相关文档或片段标注的问题集。常见指标包括 Recall@k、Precision@k、MRR、nDCG、命中率和无答案识别。对 RAG 通常先保证候选召回，再优化前几条精度和 Context 成本。

评测集应覆盖同义表达、专有名词、跨文档问题、时间条件、冲突资料、无答案和恶意内容。只用从文档标题自动生成的问题会高估真实效果。

## 生成与端到端评测

生成层评估答案正确性、忠实度、引用支持度、完整性和无答案行为。端到端还看任务成功率、延迟、Token、检索成本和用户纠正率。应保存实际检索片段和 Prompt 版本，才能定位错误来自检索还是生成。

错误分析至少分为解析失败、召回失败、排序失败、上下文组装失败、证据冲突和生成误用。只看最终平均分无法指导改进。

## 安全与权限

检索前执行租户、用户和文档权限过滤；索引、缓存和日志也需隔离。网页或文档中的 Prompt Injection 是数据，不能改变系统权限。敏感内容发送到外部模型前还需满足数据政策。

RAG 可能泄露“用户不知道但向量相似”的私有片段，因此不能在生成后才做权限过滤。引用链接也要经过授权，避免用可猜 URL 暴露原文。

## 常见失败场景

- 固定字符切块把否定条件与结论分开，命中后含义反转。
- 只使用向量检索，错误码和精确技术名无法命中。
- 旧版本文档未删除，答案混用冲突配置。
- Query Rewrite 改掉数字或否定词，检索到另一问题。
- 有引用但引用片段不支持对应主张。
- 文档恶意指令进入 Context 后诱导模型调用高权限工具。

## 生产实现检查表

保留来源与版本；按资料结构切块；建立词法基线；需要时增加向量和重排；查询保留原始约束；召回前执行权限过滤；上下文去重并标注数据边界；引用绑定真实片段；分别评测解析、检索、生成和端到端；线上记录查询、候选、选择结果、延迟与用户反馈。

## 20 秒口述

我会把 RAG 拆成解析、切块、召回、重排、上下文组装和带引用生成，而不是只选一个向量库。BM25 处理精确术语，向量处理语义改写，是否混合要看目标问题集。评测时分开看 Recall@k、前几条精度、答案忠实度和引用支持度，这样才能定位是没检索到还是模型误用了证据。

## 1 至 2 分钟展开

我先保留文档章节、版本、权限和位置，再根据文档结构切块。建立 BM25 基线，如果同义表达漏召回，再加入向量；候选多时用重排。Query Rewrite 只作为补充，原查询的实体、数字和否定条件必须保留。Context 组装会去重、控制来源多样性并把资料标成不可信数据。评测分层进行：解析正确性、Recall@k、排序、引用支持度和最终任务效果，线上 Trace 保存实际证据以便定位失败。

## 高频追问

### Chunk 多大最好

没有通用最优值。取决于文档结构、问题粒度、Embedding 模型和 Context 预算。用目标问题集对比不同策略，并分析条件被切断、多个主题混合和召回噪声。

### RAG 和微调怎么选择

RAG 适合更新知识、私有资料和引用；微调更适合调整行为、格式和稳定模式。二者可组合，但微调不适合频繁更新事实，也不天然提供来源。

### 检索不到时怎么办

先区分通用知识题与资料事实题。通用题可明确使用模型知识；涉及个人经历、内部政策或精确文档事实时应说明缺少证据、请求资料或转人工，不能编造。

## 系统设计练习

设计面试提词知识库时，按知识点标题切短段，标题包含中英文术语；用词法检索保证框架名和错误码命中，需要时增加语义检索；快速回答预算优先返回结论、机制和失败场景；个人简历与通用参考资料分开标记；引用保留文件和行号；用真实面试问题检查 Top 3 片段。
