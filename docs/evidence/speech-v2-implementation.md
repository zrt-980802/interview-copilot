# 连续语音试用实现与验证

日期：2026-11-19；开发分支：`codex/speech-pipeline`。

## 已实现的行为

- 复用现有 WASAPI 设备选择及 PortAudio 生命周期，每路独立 Silero VAD、有状态 soxr 重采样，识别和 EOT 共用有界后台调度器。
- 识别窗口目标6秒、最长12秒，优先选择自然停顿；这些预算不会结束问题。120秒音频环形缓冲仅限制内存保留。
- ASR 最终稿按音频范围记账；等待最新讲话活动的 EOT、完整识别水位、文字意图和质量检查，以及1.4秒安静稳定期。恢复讲话立即作废旧端点/待提交提案。
- 单纯场景陈述继续积累，背景流程仅作为上下文，本人发言仅进入本人上下文；有效的新技术题不要求命中个人材料。
- 识别失败、采集缺口、积压、过期、重复识别、典型 Whisper 幻觉及异常时间戳不会以残缺问题自动出题；8秒等待上限只进入待确认。
- 同题明确补充通过既有 turn 修订取消旧回答。电脑草稿支持编辑、提交、放弃，编辑先取得暂停自动提交的持有状态，刷新可恢复草稿；手机投影删除草稿字段。
- 暂停两路采集后，可在“声音采集 → 语音流程”切换兼容/连续语音。当前进程内切换保留会话、历史及手机授权；重启服务仍需要重新配对。配置未指定时保持兼容模式。

## 可重复验证

```powershell
.\venv\Scripts\python.exe -m pytest -q
.\venv\Scripts\python.exe scripts/evaluate_speech.py --output data/speech-v2/event-replay.json
.\scripts\generate_speech_fixtures.ps1
.\venv\Scripts\python.exe scripts/evaluate_speech_audio.py --output data/speech-v2/audio-report-final.json
```

Python 全量458项通过；前端 Playwright 全量58项通过，包括草稿重载/编辑/提交/放弃、手机配对、问题补充、设备选择、历史及设置。桌面1365px、390px、320px截图已检查，按钮和文字无横向溢出。

纯事件回放6/6通过；相同时间轴的旧 QuestionMerger 在4个场景提前提交。额外单测覆盖55/120秒跨窗、晚到/乱序识别、旧修订、EOT过期、草稿编辑持有、音频缺口、有界队列、队列过期、来源隔离和取消。

真实模型采用 Microsoft Huihui Desktop 生成中文 TTS，未打开录音设备。12个音频场景全部达到预设题目数量/角色决策，包含5类非语音和7条有语音样本：

| 输入 | 结果 | 标准化 CER |
| --- | --- | --- |
| 8.73秒短技术题 | 1道题 | 3.45% |
| 未完场景中停4秒再补充 | 1道完整题 | 2.50% |
| 71.28秒长题，含多个自然停顿 | 1道完整题，前提和约束保留 | 1.72% |
| 本人回答 | 记录上下文，0道面试官题 | 4.08% |
| 与个人材料无关的虚拟内存题 | 1道题 | 0% |
| 招聘流程说明 | context_only，0道题 | 0% |
| 静音、白噪声、低频声、键盘脉冲、提示音 | 各0提交 | 不适用 |
| 低音量加噪声的短题 | 1道题 | 3.45% |

3秒与6秒目标窗口的9条共有样本均保持相同提交数；文字仍存在窗口相关差异，不声明边界词完全一致。CER去除标点/空格并忽略大小写，小样本数值不能代表真实会议质量。

实际发现过的失败：初次接线仅依赖音频 EOT 时，71秒题目被提交9次；另一个6秒窗口产生“请不吝点赞…”幻觉，时间戳到29.98秒且模型分数很高。新流程增加文字意图/稳定等待/自然停顿窗口，并校验返回时间范围；典型幻觉另设待确认门控。相应错误响应已加入确定性回归。

运行环境：Windows，Python3.12，numpy2.5.2、onnxruntime1.32.0、soxr1.1.0、transformers5.16.1；ASR为本机 faster-whisper large-v3-turbo。模型固定版本和SHA见[模型来源](../speech-model-notices.md)。音频回放采用真实推理、加速音频时钟，不包含实时调度延迟；不能用其 wall_seconds 计算说完到首字的P95。

## 已知边界与后续验收

正式服务已在空闲、两路采集暂停时重启加载新版，端口仍为电脑8527、手机8528。原510条turns已备份到忽略目录，发布前后逐行摘要SHA-256一致。真实HTTP验证连续模型加载、兼容→连续→兼容切换、同一会话/手机cookie保留、手机快照无草稿；未启动采集，最终模式为legacy。该验证不生成正式问题或模型回答。备份、摘要和服务验证结果位于`data/speech-v2/`，不进入Git；此次进程重启后原手机需重新配对一次。

连续流程提供受控试用入口，未切为默认。未采集真实耳机/麦克风，也没有真人咳嗽、多人串音、数字否定或方言的统计验收；需要实际会议设备样本才能判断误触发下降比例和实时P95。

术语仍有“密等/幂等”“重视/重试”等同音误识别，质量分数未必能发现；现有回答上下文解释及可编辑草稿不能代替识别准确率。未实现强制窗口边界重识别、可校准的歧义数字否定判定或FunASR两遍后端。

本轮通过离线回放比较，不提供运行时双识别shadow；`speech.mode=shadow`明确报错，避免隐藏地多开设备/推理。实际装配直接复用legacy设备所有者和STT客户端，既有v2抽象入口未整体迁移。以上差异保留为后续工作，不计入已完成验收。
