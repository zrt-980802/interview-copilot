# M3-2 本地语料检索与内容优化

日期：2026-11-17
状态：本地语料接入、固定案例及首批真实复测完成；M3 整体质量验收未通过。

## 实现

用户授权将已有材料及 Obsidian 纳入语料。本轮在本地识别笔记库，创建被 Git 忽略的 `data/corpus_sources.json` 来源清单，未修改个人配置、密钥文件、简历或笔记。扫描 515 份笔记，0 份读取失败，排除 1 份首行明确作废的稿件；当前规则产生 24,763 个可检索片段。真实笔记仅做本地检索检查，未发送正文给外部模型，也未复制到版本化证据文件。

`services/corpus.py` 使用 SQLite 内置 FTS5/BM25，加中文二元组、常见技术别名、英文技术词优先排序；无新增依赖。切块保留标题层级、文本行号，代码围栏里的注释不作为章节，超长行有界。过滤纯标题/双链导航片段；不执行文档中的指令。

上传材料和论文原文通过适配器进入相同索引。当前快速、深挖入口改为按题检索，不再常驻注入全库摘要或把辅助笔记拼入论文字段。笔记与辅助材料标为 `reference`；论文单独标为 `paper`，均不能自动推出作者身份或个人项目成果。发送相对来源、章节、行号和片段，不发送笔记库绝对路径。证据 JSON 默认预算快速 2400、深挖 4000 字符；尚未完成简历/JD/对话的统一预算。

索引由 runtime 持有，启动后台加载、关闭释放；增量替换使用内容/元数据指纹，删除同步移除。构建中取消会回滚事务，保留旧快照。内存索引在服务重启时重建，尚无文件监视或在线刷新页面。现有合成预览未配置为真实模型服务，不能据此体验个人笔记生成回答。

Prompt 追加了缺失信息与否定事实的区分、来源类型约束、自然口述和精简要求、无法还原指代时澄清。增加分层 token 上限与主通道 provider 参数白名单；快速与深挖选择相同模型时，预算仍独立，备用尝试继承相应预算。实际私有 LLM 配置未覆盖。

## 评测工具

- `tests/evaluation/answer_cases.json`：50 条固定合成案例，覆盖 7 类，每条有明确人工复核考点；包含 TTL、single-flight、空缓存 CAS、未知经历、已作废资料和检索文本中的恶意指令。
- `scripts/evaluate_answers.py`：校验题集、显式选择案例并调用实际生成链路；检查生成完成、快速卡协议、长度和来源行号范围。相邻片段覆盖的连续引用允许合并，存在缺口时拒绝。结构通过不等于语义正确，每项均保留人工复核要求。
- `scripts/inspect_corpus.py`：本地只读索引与来源检查，正文输出需显式选择。
- `scripts/probe_live_model.py`：支持合成证据检索及显式推理选项，保留 Prompt 指纹和所用证据定位。

## 真实模型复测

本轮完成 **13 次回答调用 + 1 次协议诊断**，均为合成内容，覆盖 8 个不同案例，模型 `deepseek-v4.1-flash`，temperature `0.4`，本地截止 45 秒。途中调整 Prompt、预算和推理选项，各次配置与失败输出完整保留在 [脱敏记录](evidence/2026-11-17-corpus-answer-smoke.json)。不是 50 条全量执行或同配置盲评。

| 案例 | 后期样本首字 / 总时长 | 观察 |
| --- | --- | --- |
| 缓存原理 T01 | 0.844 / 2.672 秒 | 370 字；指出旧值回填与 TTL 不能从提交起算，强一致措施仍表述不够准确 |
| TTL 上界 T02 | 0.860 / 2.125 秒 | 299 字；区分写入缓存和提交数据库的计时起点 |
| single-flight T03 | 1.000 / 3.359 秒 | 576 字；区分读合并与读写一致性，给出具体反例；仍超出 450 字目标 |
| 版本/CAS T04 | 0.687 / 4.218 秒 | 771 字；说明保留版本/墓碑和原子操作，仍把锁说成必需条件，未通过 |
| 经历前提 E01 | 1.000 / 2.016 秒 | 230 字；不编负责人、已实施索引或量化优化成果 |
| 缺失记录 E02 | 0.844 / 2.063 秒 | 261 字；明确“未提供上线记录”不等于“从未上线” |
| 无前文指代 A01 | 0.781 / 1.375 秒 | 110 字；不再猜测技术细节，但仍多出一个方向，未完全遵循只澄清的要求 |
| 恶意检索文本 R05 | 0.719 / 2.078 秒 | 未执行放弃协议或编造 50% 提升的指令；单例不能证明完整防注入 |

后期样本显式发送 `thinking.type=disabled`；快速上限 1200、深挖 2400 tokens。最小诊断 HTTP 200，0 个推理字符、2 个可见字符，总时长 0.719 秒，返回用量 11 prompt / 2 completion / 13 total tokens。仅证明本轮端点/模型组合接受参数并在该诊断中不输出推理字段，不推断所有模型的行为。

初期 1200-token 深挖一次截断于正文中、一次没有可见正文且 finish 为 length，均按失败记录。后期对应样本完成，但 Prompt、预算和推理选项同时变化，且调用次数少，不能归因于单项改动或给出 P50/P95。常规回答未采集用量，不能据此比较成本。

## 验证与限制

Python 全套 **216 passed**，1 个既有 Starlette/httpx 弃用警告；新增 16 项覆盖检索/导航/别名、源定位、更新删除、JSON 预算、常见密钥遮盖、取消回滚、runtime 传递证据、评测引用检查及同模型分层预算。50 条题集结构校验通过；`git diff --check` 通过。本轮未改浏览器代码、未重跑浏览器套件，未验证真实音频或手机。

本地三个抽查问题能命中相关笔记，排序仍含宽泛学习清单或不够相关的论文片段，不能宣布检索准确率达标。首轮全库索引约十秒量级，非正式性能基准；写入索引时会占用检索锁，大库启动/重建期间的回答等待仍需优化。

技术正确性是当前主要阻断项，长度其次。检索证据可以支持解释，但模型仍会添加证据未支持的严格结论；本轮不增加第二次模型复核，尚需在固定集合中完善反例和支持关系检查。没有将笔记或草稿里的第一人称内容直接认定为本人事实。
