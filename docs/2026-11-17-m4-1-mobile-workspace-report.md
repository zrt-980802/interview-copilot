# M4-1 手机显示与桌面导航

日期：2026-11-17
基线：`v2-restructure` / `6be3112`，保留原工作区所有前序改动，未提交或推送。

本批完成可运行的独立手机显示端和桌面导航第一版。M4 整体、实机手机/音频及 M3 语义质量没有因此通过验收。

## 实现

`services/mobile_access.py` 管理内存授权：八位随机码 120 秒有效、单次兑换、每地址每分钟 5 次/全局 30 次限流；最多 8 台设备，当前会话有效，8 小时到期。长期凭据以 HttpOnly、SameSite=Strict Cookie 传输，服务端保存哈希。HTTPS 时设置 Secure；首版局域网 HTTP 不提供链路加密。

`legacy/mobile.py` 提供独立 FastAPI 应用，静态资源采用逐项白名单。手机只有配对/退出、授权快照与 SSE；不提供上传、清空、设备管理、历史、OpenAPI 或完整桌面静态目录。正式问题和答案来自相同 SessionManager 和 ReplayEventHub；背景来源快照、设备元数据、口述缓冲和管理状态被排除。回答中的材料摘录仍会显示，不能把元数据投影当作正文敏感信息过滤器。

私有事件被投影为纯事件游标，保证连续编号和重连去重。慢连接恢复为同一会话快照。每个数据事件及空闲检查重新验证授权；撤销、换会话或凭据到期会终止旧流并通知手机清除可见答案。已发送到网络/设备的数据无法收回，空闲流通常在下一秒检查发现撤销。

`services/listeners.py` 预先占用电脑和手机端口，再进入唯一的电脑 lifespan；手机不拥有音频、模型、历史或 corpus 的生命周期。两个监听器共享退出信号与清理流程。正常 `server.py` 入口将管理端固定在回环，手机单独绑定配置接口；模块导入不启动监听。

`static/mobile.html` 和 `static/js/mobile.js` 使用已有 Answer Document 渲染器，支持竖屏、旧题选择、跟随最新、字号、明暗与专注模式、可选屏幕常亮。手机只显示电脑已经生成的深挖；不开放生成命令。网络恢复、返回前台与刷新从事件/快照同步；重连保持旧题选择，整页刷新默认最新题。

二维码仅包含短码 fragment，页面立即清除再 POST。实测发现已打开网页再扫描相同页面二维码属于同文档导航，原先没有重新执行初始化；现补 `hashchange` 处理并纳入实际浏览器回归。

桌面增加题目侧栏、当前题标记、回到最新和手机配对对话框，工具栏采用本地 Lucide 图标。阅读旧题时新题/回答不再抢占滚动位置。保留当前材料管理和原有生成控制，本批未实现完整三栏、历史检索或材料准备重做。

页面打开不再自动录音。`--auto-listen` 在服务启动阶段选择本机回环和麦克风，支持配置设备编号；新增后台手机批处理入口，不打开电脑浏览器。采集 start/stop 按通道串行处理，重复 start 保持幂等，状态根据实际引擎线程刷新，设备退出不再一直显示采集中。STT/LLM 完整自检及后台进程的专用退出入口尚未实现。

`scripts/launch.ps1` 替换固定 ping 等待：读取配置端口、检查健康服务标识与 ready、记录后台进程日志并检查退出；已运行但不 ready 的服务不会被当成空端口启动第二个进程。设置本机 STT 目录时按配置探测 `/models` 并等待。原服务没有手机监听时明确报错，不自动终止当前会话。

依赖新增 `qrcode>=8,<9`，二维码为库生成 SVG；图标为本地 Lucide 0.468.0，保留第三方许可，无运行时 CDN。

## 证据与入口

- 截图：`docs/evidence/m4-1-ui/`，包括 `workspace-desktop.png`、`pairing-desktop.png`、`phone-answer.png`、`phone-320x740-large.png` 和 `phone-light-focus.png`。二维码图片为已撤销的合成测试配对。
- 当前本机合成预览：电脑 `http://127.0.0.1:8540`，手机界面 `http://127.0.0.1:8541`。仅绑定回环；这两个地址不能在另一台手机直接访问。正常使用按 [手机显示说明](mobile-display.md) 启动独立局域网端口。
- 后台启动：`start-phone.bat`；终端方式：`venv\Scripts\python.exe server.py --mobile --auto-listen`。
