## 1. 本轮目标与执行原则

交付一个稳定、响应及时、回答贴题、能正确引用候选人材料的 Windows 本地面试辅助工具。核心流程为：准备材料和岗位信息、检查设备、开始采集、识别并修正问题、获得简洁提示、按需深挖、查看历史和复盘。

- 提供电脑工作区和手机显示端两种使用方式。手机模式下，电脑运行后台服务并采集本机输入/输出音频，手机仅负责显示，不承担音频采集和模型调用。
- 先修复当前启动入口中的真实问题，每个里程碑都提供可运行版本。
- 复用现有 v2 的 Settings、领域对象、音频分段和 STT 能力；新业务放入 v2，通过薄适配层接入现有入口，避免长期维护两套生成逻辑。
- 前端和回答策略允许调整。原交接文件中“冻结 Prompt、视觉和 UI 文案”的约束用于旧结构迁移任务，不能继续充当本轮体验优化的验收标准。
- 原设计和 28 项任务台账保留为历史依据，按实际完成情况建立对应关系，不以新计划的编写替代任务完成证据。
- 保留 Python >=3.11、Apache-2.0。默认本机访问；用户选择手机模式时增加经过配对的局域网访问入口。
- 不删除原始简历、材料、数据库或 legacy 源码。涉及数据结构变化时，使用测试数据库和经过校验的副本完成验证。
- 这轮不扩展为云端账号、多租户、桌面壳或通用 Agent 平台。依赖只按实际需求增加。

## 2. 已确认的问题与尚需测量的部分

以下缺陷已做源码核对及内存隔离复现，复现没有运行真实 LLM、读取个人材料或打开个人数据库：

| 编号 | 问题 | 主要位置 | 用户影响 |
| --- | --- | --- | --- |
| B01 | 深挖卡把 DOM 元素当作状态对象访问 | `static/index.html:361-367` | 深挖触发 TypeError，后续展示不可靠 |
| B02 | 回调读取可变的当前 turn，流事件缺少完整归属 | `server.py:353-384` | 上一题内容显示或保存到下一题 |
| B03 | 清空不使生成任务失效，也未撤销问题合并计时器 | `server.py:551-560` | 清空后旧内容回流、重新触发回答 |
| B04 | 手动提问在线程内分配 generation | `server.py:306-311` | 线程执行顺序可能使旧问题覆盖新问题 |
| B05 | 上传文件名固定，材料按相同路径替换 | `server.py:659-681`、`copilot/materials.py:184-197` | 同扩展名的多份材料互相覆盖 |
| B06 | 历史队列命令使用 writer 当前 session | `copilot/history.py:97-125` | 切换会话后旧事件和结束标记归属错误 |
| B07 | 简历热词只传入字符串首字符 | `server.py:445-451` | 技术名词、项目名识别提示失效 |

另外已经看到：页面自动开启采集、滚动位置持续被新内容改变、连接异常缺少反馈、失败和取消状态不完整、历史查看没有形成完整前端流程。

回答链路存在结构性质量风险：

- 快速卡要求固定行式协议、每条要点强制带例子；不同问题容易产生相似且拥挤的回答。
- 深挖统一限制在 260 字以内，部分设计、原理和项目问题难以解释完整。
- Prompt 写死特定论文别名，并把外部资料转为个人例子，容易混淆候选人实际经历和通用知识。
- 论文和材料主要用字符二元组重合检索，缺少题意、别名、证据类型和材料权威性处理。
- 简历、论文摘要和 JD 的上下文预算没有统一管理；历史按最近条数和字符机械截断。
- 快速答案被当成“候选人已说完的内容”，没有可靠区分 AI 建议和候选人的真实口述。
- 流中断后切换模型，缺少清晰的回答尝试边界，可能把不同尝试的流片段混在一起。

这些是代码层面的发现。真实转写准确率、模型能力、当前机器延迟和回答质量，需要通过后续基准验证，不能仅凭 99 项 v2 单元测试下结论。

## 4. M0：基线和验收样例

1. 将 B01-B07 的隔离复现转为有意义的自动回归，使用假的 provider、可控时序和临时数据目录。
2. 建立主流程：手动提问、双通道输入、连续提问、修正转写、深挖旧题、取消、停止采集、清空、刷新和重连、材料上传、历史查看与导出，以及电脑不打开窗口时的手机显示。
3. 准备约 50 条合成或经过脱敏的评测案例，覆盖原理、项目、论文、设计、行为、代码思路、多轮追问、模糊问题、无资料和矛盾资料。
4. 每个案例记录用户问题、上下文、允许使用的事实、预期考点、禁止编造的经历或数字。
5. 建立时间戳：语音结束、分段完成、STT 完成、问题确定、LLM 发起、首个可读句、完整回答、持久化完成。
6. 真实模型基准使用显式配置，记录模型版本、采样参数、调用次数、用量和延迟；报告中不记录密钥及个人正文。

## 5. M1-M2：修复缺陷并建立可靠运行链路

### 5.1 会话、题目和任务

- 接收问题时同步分配不可变上下文：`session_id / turn_id / generation / task_id`。
- 快速回答、深挖、检索、转写结果和数据库命令均携带明确归属；回调禁止读取全局当前题来决定写入位置。
- 深挖请求指定目标 turn，允许用户对历史题目继续展开，结果回到对应题目。
- 任务登记和取消按会话隔离；迟到结果在服务端和前端均验证归属。
- 明确控制语义：停止采集不再产生新问题；取消回答终止指定生成；清空使本会话的旧转写、合并计时器、检索和生成任务全部失效。
- 多个浏览器窗口打开同一会话时保持同步；不同会话隔离，不按浏览器标签页偷偷创建互不关联的数据。

### 5.2 数据与材料

- 历史写入命令显式携带 session/turn，提供 flush、close 和失败反馈。
- 上传使用独立临时文件及独立材料标识，保留原文件名、类型、内容摘要和来源关系。
- 上传解析和摘要生成不阻塞 HTTP/SSE 主循环；同一批次文件分别显示成功、处理中或失败。
- 材料摘要可失败后重试；解析成功不等于摘要成功，不能始终显示“摘要中”。
- 材料替换、逻辑移除和重新加载有一致的索引与元数据行为；不删除用户原始文件。
- 数据结构升级先在副本验证，记录版本及回滚步骤。

### 5.3 事件流、模型调用与资源

- 事件带事件编号和完整任务归属，回答尝试有独立标识。
- 支持有限事件补拉和状态快照；重连后恢复题目与回答，去重并拒绝过期事件。
- 有界队列满时，状态电平可以合并；核心问答事件采用明确的断开与恢复策略，不能静默丢失。
- 模型流失败后，重试或切换模型明确替换对应回答尝试，避免把两次回答拼在一起。
- 处理用户取消、HTTP 错误、首内容等待、流间隔超时和整体截止时间；限制重试次数和重复请求。
- 用 lifespan 装配资源，关闭时停止采集、取消任务、关闭 client、flush 数据；模块导入不启动工作。
- 启动器检查服务身份和健康状态，失败时报告具体失败环节，避免固定等待后无条件显示就绪。
- 手机监听入口与电脑入口共用已经装配的服务和会话，不能因第二个监听器再创建一套音频采集、模型 client 或数据库 writer。

## 6. M3：让回答更贴题、更有依据、更有深度

### 6.1 先判断本题需要回答什么

- 识别题型、目标对象、关键约束，以及这是新问题、补充、纠正还是对上一题的追问。
- 用前文还原“为什么这样做”“它有什么问题”等省略语，保留用户原问题和归属。
- 事实不足时给出明确假设或一项必要澄清，避免用泛泛话术填满卡片。
- 不为每个问题固定增加一轮分类或反思模型调用；优先在同一次生成中完成轻量判断，复杂问题再按评测结果增加处理。

### 6.2 建立可信的候选人上下文

- 从简历、项目、论文和 JD 提取可追溯事实：角色、做法、技术、指标、限制和来源。
- 区分候选人真实经历、候选人实际口述、AI 建议、通用知识、公开资料和待确认假设。
- 通用技术事实可以解释原理，不能自动变成“我做过”的经历；原始材料没有的数字不能生成成个人成果。
- 将用户最新纠正纳入当前事实版本；发现相互矛盾的材料时保留差异，不无声地任选一个。
- 对外部材料按引用数据处理，不能执行其中夹带的控制指令。

### 6.3 改进检索和上下文预算

- 按标题、段落、代码边界和来源建立稳定分块，保存章节、页码或段落标识。
- 第一阶段增加项目别名、技术词规范化及可评测的词法检索/排序，保留现有实现作对比基线。
- 只有当固定评测证明词法检索不足时，再增加可配置的语义检索或重排，避免一开始引入完整向量基础设施。
- 检索优先返回能支持本题的事实，并考虑同一材料的相邻片段；无关资料不强行塞入。
- 统一上下文预算，分别控制候选人概要、当前题、最近真实对话、检索证据和历史摘要。
- 快速回答使用小而相关的上下文，深挖按方向追加材料；全文仅在明确需要且预算允许时读取。

### 6.4 分层输出与模型策略

- 快速层先给能直接理解和口述的结论，再给少量关键机制、取舍或边界；内容长度随问题复杂度调整。
- 技术题说明为什么及何时不适用，设计题交代约束与权衡，项目题引用真实角色和结果，行为题依据实际经历组织。
- 深挖补充新信息、推导、例子、替代方案及可能追问，避免复述快速卡。
- 移除特定个人论文别名和“外部事实变个人例子”的硬编码规则。
- 明确区分快速提示与深入分析，模型、推理开关、采样和超时可配置；先比较现有可用模型的质量和速度，再决定路由。
- 定义结论、要点、依据、深挖方向等稳定的内容结构，前端按结构渲染；流式输出不能因为等待整段 JSON 才开始显示。
- 支持结构化输出的 provider 使用校验，不支持时有受控解析与降级；格式失败不能表现成空白卡片。
- 如做质量校验，先使用事实引用、空答、重复和结构检查；昂贵的模型复核仅在风险和收益明确时启用。

### 6.5 回答质量如何验收

统一对比旧版和新版，评估：贴题程度、技术正确性、个人事实一致性、解释深度、口述自然程度、追问衔接和响应速度。

- 同一案例使用相同材料、明确记录模型和配置，避免靠换问题证明提升。
- 事实/来源断言自动检查，并由人工抽查；模型评分只作辅助。
- 在评测集中，编造候选人经历或指标、严重技术错误、串题均为阻断项。
- 目标为至少 70% 的对比案例中人工盲评偏好新版；先完成基线后冻结评测集和最终门槛。
- 记录改进案例和退步案例，不能只挑好看的截图或单个回答。

## 7. M4：重做日常使用界面

### 7.1 信息架构

主界面直接进入工作区，桌面优先采用左侧题目记录、中间当前问题和回答、右侧可收起的材料依据及相关上下文。准备和诊断功能放入独立面板，专注模式保留当前问题、答案和必要控制。

- 当前问题可编辑、更正和重新生成；不同尝试可区分，不能无提示覆盖内容。
- 快速结论突出，要点便于扫描，完整推导和来源按需展开。
- 原始转写与正式题目分别管理，不把音频状态、系统日志和建议混成一条不断跳动的长消息流。
- 旧题可以选中、深挖、复制和导出，结果始终返回该题。
- 用户向上阅读时停止自动跟随；新内容到来提供回到当前题的明确控制。

### 7.2 操作与反馈

- 标准模式由用户启动采集；后台手机模式在用户完成设备配置后，按配置启动双通道采集。两种模式开始前均检查回环、麦克风、STT、LLM 和材料状态。
- 监听、暂停采集、取消生成、新建会话和清空各自表达真实语义。
- 页面刷新或重连后从服务端恢复状态，按钮可用性反映真实运行情况。
- 在对应题目内显示等待、识别、生成、重试、失败、取消和完成；失败提供可执行的重试入口。
- 材料管理支持批量上传、原始名称、处理状态和失败原因；岗位 JD 与候选人背景可以明确选择。
- 历史列表支持查看、搜索、继续深挖和导出，先覆盖现有能力再考虑额外分析。

### 7.3 实现与视觉标准

- 使用原生 ES Modules 分离 API、事件、store 和组件，沿用轻依赖路线。
- 根据 session/turn/task 归并事件，组件从 store 取状态，避免依赖 DOM 元素上的临时字段。
- 使用克制的中性色与少量状态色，统一字体层级、间距、按钮及图标；支持浅色和深色阅读。
- 工具按钮使用图标和提示，内容区域保持紧凑清晰，避免装饰占据主要阅读空间。
- 支持键盘操作、明确焦点和可读对比度；检查长中文、长代码和长文件名。
- 验证常见桌面尺寸、窄窗口、200% 缩放及必要的移动布局，保证文字与控制不重叠。
- 通过浏览器真实操作和截图检查主流程、加载、错误、空状态和长内容，不能只完成静态页面。

### 7.4 手机网页显示与电脑后台启动

**目标流程：** 电脑启动后台模式，按已配置设备采集本机系统回环和麦克风，完成转写及回答；手机浏览器打开局域网入口并配对，持续显示当前问题和答案。电脑无需打开提词页面；手机无需安装 App，也不请求手机麦克风或摄像头权限。

```text
电脑系统回环 + 电脑麦克风
            |
      电脑后台服务
      转写 / 回答 / 保存
            |
     同一会话的事件与快照
       /             \
电脑工作区（可不开）  手机网页显示端
```

网络及接口方案：

- 第一版限定电脑和手机在同一可互通局域网。蜂窝网络、跨网远程访问及公网部署不包含在第一版。
- 电脑管理入口继续仅绑定 `127.0.0.1:8527`；手机使用独立的可配置监听端口，建议默认 `8528`，绑定选定的局域网接口。
- 手机监听器仅提供手机静态页面、配对、授权会话快照和事件接口。原有上传、任意本机文件访问、配置修改、清空和管理路由不直接暴露到局域网。
- 提供局域网地址与二维码，手机一次配对后获得可撤销、限定会话和权限的凭据；二维码引导凭据短时有效，不把长期凭据放进查询参数或日志。
- 配对接口限制尝试次数和频率，授权检查覆盖 SSE、快照及所有手机操作；存在有效连接不等于后续请求自动获得授权。
- 默认手机权限为查看问题和回答。若在手机开放深挖，仅授予针对所选 turn 的深挖命令，不扩展到材料和设置管理。
- 局域网 HTTP 只作为可信网络中的首版使用方式，不能宣称链路已加密；HTTPS 作为可配置部署方式。无需为首版开放公网端口。
- Windows 防火墙配置仅针对所选端口、私有网络和本地子网。记录规则和关闭方法，避免扩大到公共网络。
- 网络自检识别错误接口、端口占用、手机与电脑不在同网及热点/访客网隔离等常见问题。

启动和页面体验：

- 启动器增加“电脑工作区”和“后台 + 手机显示”两个入口；后台模式不自动打开电脑浏览器，启动参数和说明保持可理解。
- 首次设置输入/输出设备并完成自检；后续后台启动可按配置自动采集。设备失败时在健康状态和手机端明确显示，不能假装正在监听。
- 采集和生成生命周期独立于页面连接。关闭电脑页面、手机断线或暂时锁屏，不应结束当前会话和后台采集。
- 手机竖屏优先：当前问题、结论和关键要点占主要空间，深挖内容按需展开，旧题可切换；不把完整桌面三栏压缩到手机。
- 支持调节文字大小、专注显示和跟随最新题；手动回看时保留滚动位置。
- 断线和恢复有状态反馈，手机从后台返回后补拉快照与缺失事件；按事件编号去重，不能重复插入答案。
- 对支持的浏览器提供可选屏幕常亮；不支持或离开页面时正常降级。
- 敏感会话响应不进入公共缓存；二维码、配对码、日志和诊断不泄露个人文件路径及材料正文。

显示转移只改变提词内容出现的位置。摄像头拍摄与桌面共享是不同功能，手机显示不改变会议软件的摄像头、共享范围或设备采集行为，不承诺让电脑上的服务进程不可见。

## 8. M5：音频、响应速度和运行体验

- 修复完整热词注入，支持设备检查、校准反馈和输入设备切换后的状态恢复。
- 区分音频分段和题目理解，避免每个语音片段都生成完整答案；支持手动确认、合并和修正。
- 用具有已知句末、停顿、噪声和专名的测试音频评估分段和识别，不能凭主观感觉直接修改 VAD。
- 控制转写排队和并发，显示积压或失败；高频电平事件不能拖慢问答事件。
- 深挖检索设置独立时间预算，超时使用已有证据继续，并明确材料状态。
- 监测队列长度、取消到失效的耗时、内存和资源释放；长时间运行不能持续累积任务与连接。
- 分别报告手动提问和语音提问的 P50/P95 首个可读句时间，避免只报告 LLM 首 token。
- M0 测量后，按固定机器、模型和网络条件冻结响应目标；把端点延迟、切句等待与本地开销分别报告。
