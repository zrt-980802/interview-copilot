# M3-3 上下文预算、聚焦检索与全题集评测

日期：2026-11-17

状态：输入预算、本地澄清及检索收敛已实现，完整题集已执行；回答语义质量仍未通过 M3 验收。

## 已实现

- `services/answer_context.py` 统一管理完整消息输入，包含系统规则、资料 JSON、对话和当前问题。默认快速 16000、深挖 24000 个序列化字符；不是精确 token 预算。完整保留当前问题及方向，对简历、本人发言、证据、历史等分配剩余空间，并标记 `context_coverage.partial_fields`。必需内容自身超限时，在 HTTP 请求前拒绝，不静默截断问题。
- 简历较长时保留开头和按题相关段落；历史保留最近完整消息，AI 建议与本人实际发言保持分离。预算计算含 JSON 引号、转义及字段开销，不修改调用者数据。
- 没有前文或本人发言的少数明确指代短问，直接产生一条澄清，不调用模型；有上下文或题目带具体技术对象时继续走模型。本地回答仍有正常尝试、取消和完成生命周期，标识 `local:clarification`。
- 英文技术词在正文或末级标题有命中时，限制在这些片段中排序，减少同篇笔记的无关章节；无命中则保留词法回退。保留单一来源的多段相关证据与多来源多样性。该策略可能牺牲仅使用同义表述的召回，尚不支持宣称检索准确率达标。
- 检索证据附可复制的 `citation`；片段缩短时同步收紧行号和引用。上传材料与论文的来源包含独立标识及原文件名，同名文件可区分。PDF 行号仍指提取文本。
- 评测支持旧提示词快照、显式全量运行和互斥的推理开关。记录题集、案例、提示词、消息哈希与上下文大小；区分本地澄清和 provider 尝试。引用检查新增格式错误检测，避免把无法解析的引用漏报为通过。

没有改动个人笔记、简历、私有配置或持久化密钥。本批所有联网内容均为合成材料，没有把真实 Obsidian 正文发送给模型。
