# Windows 首次安装与准备状态

本文面向首次从源码运行 Interview Copilot 的 Windows 试用者。页面、回答模型、实时转写、音频设备、录音归档和离线精转写是相互独立的准备项；其中一项可用不代表其他项已经可用。

## 1. 找到实际 Python

项目声明支持 Python 3.11 及以上。首次安装流程已在 Windows CPython 3.11.15 上验证。先检查命令实际指向的位置和版本：

```powershell
py -0p
Get-Command python -All
python --version
```

`py -3.11` 只适用于 Launcher 中注册了标准 `3.11` 标签的解释器。Astral/uv 等发行方式可能显示为厂商标签，此时使用 `py -0p` 输出的完整标签：

```powershell
py -V:Astral/CPython3.11.15 --version
py -V:Astral/CPython3.11.15 -m venv venv
```

如果使用 uv，可直接取得其管理的解释器路径：

```powershell
uv python find 3.11
$python = uv python find 3.11
& $python --version
& $python -m venv venv
```

不要仅凭 `python` 命令存在就继续；Windows Store 别名、其他工具的 venv 或旧版本都可能先出现在 PATH 中。

## 2. 安装且不覆盖已有配置

在仓库根目录执行：

```powershell
.\venv\Scripts\python.exe -m pip install -e '.[audio,pdf]'
if (!(Test-Path .\config.json)) { Copy-Item .\config.example.json .\config.json }
.\venv\Scripts\python.exe --version
.\venv\Scripts\python.exe server.py
```

安装依赖可能访问配置的 Python 包索引。复制模板只用于首次安装；已有 `config.json` 时不要覆盖。历史、资料、Provider 设置和录音保存在受 Git 忽略保护的本地位置，升级不应删除这些数据。

服务默认地址是 `http://127.0.0.1:8527`。另开 PowerShell 可检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8527/api/health
```

`ready: true` 表示本地页面及运行时已经启动，不表示外部模型、STT、音频设备或本地权重已经通过测试。

## 3. 分项判断准备状态

| 项目 | 页面如何显示 | 如何验证 | 未准备时的实际影响 |
| --- | --- | --- | --- |
| 本地页面 | `/api/health` 为 `ready: true` | 打开工作区并检查健康接口 | 页面或 API 不可用 |
| 回答模型 | 面试准备区显示未配置或“连接未检查” | 在“模型设置”填自己的 OpenAI-compatible 服务并点击测试连接 | 页面仍可打开；普通问题不能生成远程模型回答 |
| 实时转写 | 独立显示未配置、本机/远程服务和“连接未检查” | 准备 STT 服务后用合成或非敏感音频实际监听 | 手动文本提问仍可使用；语音不会可靠形成问题 |
| 播放设备和麦克风 | 分别显示设备、未发现、未连接或监听状态 | 在声音设置选择设备，开始监听并观察音量/语音状态 | 对应通道不采集；不应把页面可用视为设备可用 |
| 录音归档 | 显示已开启、关闭、归档中或缺口 | 在“模型设置”的录音区域核对并按需关闭 | 关闭后不保存新会话录音；既有录音不受影响 |
| 离线精转写 | 显示运行环境和本地权重是否准备 | 安装 `.[offline-asr]` 并提前准备本地模型，再对合成录音运行 | 录音仍可保存，但结束后不能完成本地精转写 |

准备区不会为了检查状态主动调用远程模型或 STT。连接状态必须由用户显式测试或用受控合成输入验证。

## 4. 配置自己的回答服务

`config.example.json` 中的 `api.example.invalid` 和模型名是安全占位符，不能生成真实回答。打开 `/settings` 配置自己的服务、模型和 API key：

- 获取模型会访问所选服务的 `/models`。
- 测试连接会向 `/chat/completions` 发送固定、无个人资料的短请求。
- 这些请求会离开电脑，服务商可能记录请求并计费。
- 密钥不要写入 README、命令历史、源码或报告。可使用设置页的 Windows 用户级加密存储，或只在启动进程中提供环境变量。
- 页面显示“已配置”只表示必填字段完整；以显式连接测试和实际合成问题为准。

## 5. 实时 STT 是独立服务

模板默认 `http://127.0.0.1:8760/v1`，但本仓库不会自动安装 STT 服务或下载模型。要使用实时语音，需自行准备兼容 `/audio/transcriptions` 的服务，并让 `stt.url`、`stt.model` 与该服务一致。

使用本机回环地址时，音频发往本机 STT 进程。改成远程地址后，采集到的语音片段会发送给该服务，可能包含敏感内容并产生费用。`/models` 可访问只说明 API 进程响应，不证明模型已经加载或转写质量合格。

STT 不可达不会阻止本地页面启动。此时不要开启自动采集进行正式面试；可先用手动文本问题验证界面和回答服务。

## 6. 录音、数据流和费用

- 新安装默认开启会话录音和结束后本地精转写。设置页提供明确的状态及关闭入口；已有用户保存的关闭或设备选择不会被模板覆盖。
- 麦克风和系统声音按通道分别保存到 `data/recordings/`。结束面试后可在历史页检查、转写和导出。
- 离线精转写使用本机 faster-whisper，不发送给回答 Provider；当前设备默认保持 `auto`，优先尝试 CUDA并可回退 CPU int8。用户也可显式选择 CPU 或 CUDA。
- 离线权重不会自动下载。缺少依赖或权重时页面会如实显示未准备，录音仍可保存。
- 手动问题、选中的资料片段和对话上下文会发送给用户配置的回答 Provider，可能产生模型费用。
- 实时音频只发送给 `stt.url` 指定的服务；本机和远程地址的数据边界不同。
- 本地录音、历史和导出不会自动上传，但内容仍可能敏感，分享前需自行检查。

## 7. 常见阻塞

- `py -3.11` 找不到解释器：使用 `py -0p` 的完整标签，或 `uv python find 3.11` 返回的绝对路径。
- `python` 打开商店或版本不对：不要继续使用该别名；显式调用已核对版本的解释器创建 venv。
- 页面打开但回答失败：检查 `/settings` 是否仍是 `.invalid` 占位地址，并显式测试连接。
- 页面打开但没有语音：先确认独立 STT 服务、模型和端口，再确认系统播放设备与麦克风；这两类问题相互独立。
- 录音存在但精转写未开始：检查 `.[offline-asr]` 依赖、本地权重和录音设置。应用不会替你下载权重。
- 端口被占用：先确认占用进程身份，不要直接终止未知或正式服务；可在私有 `config.json` 中选择其他电脑端口。

首次真实会议前，至少完成一次无敏感内容的文本问题、一次受控合成音频转写、录音结束和本地导出检查。真实耳机、麦克风、会议软件回环和远程服务费用仍需按试用者自己的环境验收。
