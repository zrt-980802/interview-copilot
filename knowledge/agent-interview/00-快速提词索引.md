# Agent 开发快速提词索引

用途：面试现场先开口，再根据追问进入对应专题。以下内容是通用口述骨架，不代表个人项目事实。

## Agent 与普通工作流有什么区别

开口：我会把 Agent 定义为由模型动态决定下一步行动的任务系统；固定 Workflow 的控制流主要由代码预先确定。工程上两者不是二选一，可靠系统通常以确定性工作流限定边界，只在需要语义判断、任务分解或工具选择的位置交给模型。

深挖入口：控制权、状态机、终止条件、Human-in-the-loop，见《01-Agent架构与执行循环》。

## Agent 的核心循环是什么

开口：核心循环是读取目标和当前状态，选择下一步动作，执行工具并记录观察结果，再判断完成、重规划或停止。每一步都要有预算、权限和可验证的完成条件，不能只相信模型输出“已经完成”。

深挖入口：Observe-Plan-Act、控制器、检查点，见《01-Agent架构与执行循环》。

## ReAct 与 Plan-and-Execute 怎么选择

开口：ReAct 适合步骤较短、观察结果会频繁改变下一步的任务；Plan-and-Execute 适合可以先形成阶段目标、再逐步执行的长任务。生产中常组合使用：先生成粗粒度计划，每一步内部用短 ReAct，并在关键事实变化时重规划。

深挖入口：规划粒度、反思、Verifier，见《02-Agent规划推理与任务分解》。

## 怎样防止 Agent 无限循环

开口：不能只靠 Prompt 要求停止。我会设置最大步骤、时间、Token 和费用预算，对重复动作和无状态进展做检测；完成必须通过结构化条件或外部验证，超过预算后进入澄清、人工接管或安全失败状态。

深挖入口：终止条件、进展度量、重规划，见《01》和《02》。

## Tool Calling 的主要风险是什么

开口：模型选择工具和生成参数都不是可信结果，工具执行也可能超时或产生副作用。我会在模型与工具之间增加 Schema 校验、业务校验、权限检查和幂等控制，并对高风险操作要求人工确认。

深挖入口：副作用、重试、权限、沙箱，见《03-Agent-Tool-Calling与工具工程》。

## 工具超时后为什么不能直接重试

开口：超时只表示调用方没有及时收到结果，不代表服务端没有执行。查询操作通常可以重试；支付、发消息、创建工单等操作必须依赖幂等键、状态查询或补偿机制，否则可能重复产生副作用。

深挖入口：至少一次执行、幂等键、状态机，见《03》。

## Context 与 Memory 有什么区别

开口：Context 是本次模型调用实际可见的输入；Memory 是跨步骤或跨会话保存、以后可检索的状态。Memory 只有经过选择并注入 Context 才能影响模型，所以关键是写入准入、检索相关性、冲突处理和预算，而不是无限保存对话。

深挖入口：工作记忆、情景记忆、语义记忆，见《04-Agent-Context与Memory》。

## 长期记忆应该保存什么

开口：优先保存稳定、可复用、有来源的事实和任务结果，不直接把模型推断当成用户事实。每条记忆应带来源、时间、作用域和置信状态；敏感信息、短期噪声和未经确认的推测默认不进入长期记忆。

深挖入口：写入策略、遗忘、冲突，见《04》。

## RAG 的完整链路是什么

开口：链路包括文档解析与清洗、按语义和结构切块、建立词法或向量索引、查询改写、候选召回、重排、上下文组装、带引用生成以及离线和在线评测。Embedding 只是其中一个环节，不等于完整 RAG。

深挖入口：Chunking、Hybrid Search、Rerank，见《05-Agent-RAG与知识库》。

## 向量检索和 BM25 怎么选

开口：BM25 擅长精确术语、编号、错误码和专有名词；向量检索擅长语义近似表达。实际知识库通常采用混合召回，再通过重排和元数据过滤提高精度，但是否值得增加复杂度要用目标问题集验证。

深挖入口：召回率、精确率、RRF，见《05》。

## 怎样评测 Agent

开口：我会分三层评测：最终任务是否成功、执行轨迹是否合理、系统运行是否满足延迟成本和安全要求。最终答案正确不代表过程安全，过程看似合理也不代表任务真的完成，因此需要规则、环境状态和人工评审组合验证。

深挖入口：Golden Set、模拟工具、轨迹评测，见《06-Agent评测》。

## LLM-as-Judge 能否作为唯一评审

开口：不能。它适合评估开放式质量，但会受到提示、顺序、长度和模型偏好的影响。客观条件优先用代码和环境状态验证，主观质量使用盲评、成对比较和人工抽检，并定期校准 Judge 与人工结论的一致性。

深挖入口：评审偏差、置信区间、回归门禁，见《06》。

## 什么时候需要多 Agent

开口：多 Agent 只在工具、权限或 Context 需要隔离，且子任务可独立验收或并行时才有价值。我会先做单 Agent 基线，再比较成功率、P95、Token 与调试成本，而不是默认增加角色。

深挖入口：Router、Supervisor、Handoff、交接契约和全局预算，见《07-Agent多智能体协作与编排》。

## MCP 和 Function Calling 有什么区别

开口：Function Calling 是模型向应用表达结构化动作的机制；MCP 是 Host 与外部 Server 发现和调用工具与上下文的接入协议。MCP 不会替代应用层的资源授权、幂等和安全校验。

深挖入口：Host/Client/Server、Tools/Resources、A2A 与框架选型，见《08-Agent协议MCP与框架选型》。

## 结构化输出能防幻觉吗

开口：不能。Schema 可以保证字段和类型，但不保证数值真实、工具适用或资源有权访问。应用仍要做事实证据、跨字段业务校验和服务端授权。

深挖入口：Prompt 分层、Few-shot、JSON mode、Schema 与版本化，见《09-Agent-Prompt与结构化输出》。

## Prompt Injection 无法完全阻止怎么办

开口：我会假设模型可能被误导，把安全边界放在系统层：最小权限、资源级授权、凭据隔离、参数校验、网络沙箱和高风险确认，用纵深防御限制影响。

深挖入口：威胁建模、认证/授权、数据隔离、沙箱和审计，见《10-Agent-Prompt-Injection安全权限与治理》。

## 线上 Agent 答错了怎么排查

开口：先用 Trace 判断错误在输入、检索、规划、工具、状态、合并还是生成层，再检查当时的模型、Prompt、工具和数据版本，用固定 Observation 与 Fake 工具复现控制流。

深挖入口：Trace/Span、Logs/Metrics、重放边界、SLO 和脱敏，见《11-Agent可观测性与故障排查》。

## 怎样降低 Agent 延迟与成本

开口：先用 Trace 分解排队、模型、检索和工具的关键路径，再减少无用轮次与 Context、并行无依赖工作、缓存稳定结果并做模型路由。成本看每成功任务，不只看 Token 单价。

深挖入口：有界队列、背压、重试、Singleflight、降级和 Canary，见《12-Agent生产部署性能与成本》。

## Self-Attention 怎样工作

开口：每个位置生成 Query，与其他位置的 Key 计算关联权重，再对 Value 加权汇总。多头注意力学习不同关系，自回归生成用因果遮罩不看未来 Token，并需要位置信息表达顺序。

深挖入口：Tokenization、Embedding、Temperature、KV Cache、prefill/decode 和幻觉，见《13-Agent大模型与Transformer基础》。

## Prompt、RAG 和微调怎么选

开口：Prompt 适合说明任务与格式，RAG 适合频繁更新、需要授权与引用的事实，微调适合大量稳定且可示范的行为模式。我会先做 Prompt/RAG 基线，再用数据证明微调值得。

深挖入口：SFT、LoRA、偏好优化、蒸馏、量化和自托管，见《14-模型选择微调与推理优化》。

## Python async 适合 Agent 的哪些环节

开口：asyncio 适合高并发的模型、检索和工具 I/O，协程在 await 时让出事件循环。它不会加速 CPU 工作：同步 I/O 用有界线程池，CPU 重任务用进程或独立服务。

深挖入口：TaskGroup、取消、Semaphore、队列幂等、Outbox 和 Saga，见《15-Agent-Python异步与分布式基础》。

## Agent 系统设计怎样开始

开口：我先问目标用户、高频任务、是否会产生副作用，并定义可验证成功、禁止动作和 SLO。然后设计信任边界、权威状态、主链路、故障恢复和评测，最后才选模型和框架。

深挖入口：八步骨架、状态机、故障模型、存储和容量估算，见《16-Agent系统设计方法》。

## 不同 Agent 案例的验证点有什么不同

开口：Research Agent 看 Claim 与引用，Coding Agent 看测试、diff 与沙箱，客服 Agent 看政策服务和真实订单状态，Data Agent 看可重现 SQL、指标口径与权限。架构由成功证据和失败代价决定。

深挖入口：Research、Coding、Customer Support 和 Data Analyst 四类案例，见《17-Agent典型系统设计案例》。

## 如何用一分钟介绍 Agent 项目

开口：我会用五句话说清目标用户和问题、可验证目标、主链路、自己直接负责的部分，以及有口径的结果与当前边界。没有做过或没有测量的内容不写成过去事实。

深挖入口：个人贡献、技术取舍、指标口径、故障复盘和事实边界，见《18-Agent项目追问与技术表达》。
