# 会话录音与本地精转写

## 使用

1. 在设置的“会话录音与精转写”中选择是否保存录音、结束后自动转写、本地模型及计算设备。这组设置独立于回答 Provider，不使用 API key。
2. 开始采集后，当前会话分别保存麦克风和系统声音，包括静音、校准阶段及未被实时转写接受的片段。只保存已开启的输入通道；关闭页面不会停止后台采集。
3. 点击工作区“结束面试”，停止两路采集、封存旧会话并打开历史。此时新建一个空会话，手机配对继续跟随。普通“新对话”会封存旧录音并轮转到新会话，采集继续。
4. 历史中的“会话录音与精转写”支持逐片段播放、启动或继续转写、人工核对、导出转写与实时识别对照。离线任务在后台进行，页面关闭后继续。

默认开启保存及结束后转写，默认精转写模型为 `large-v3`。模型未准备时显示“等待本地模型权重”，录音仍然保存；当前不自动下载权重。后续准备好模型后可点击“本地精转写”。也可手动选择机器已有的 Turbo 或 medium。

## 本地运行

录音通过本地文件和子进程管道交给 faster-whisper，不调用实时 STT HTTP 服务，也不提交给回答 Provider。推理强制离线，只加载已有模型。GPU 自动模式优先 CUDA，模型加载失败时尝试 CPU int8；显式选择 CUDA 时失败不会悄悄切换设备。

运行时优先复用 STT 项目的虚拟环境：Windows 为 `stt.server_dir/venv/Scripts/python.exe`，macOS 为 `stt.server_dir/venv/bin/python`；未配置时使用主服务 Python。对应环境需要 `faster-whisper` 可选依赖（项目 extra 为 `offline-asr`）。模型目录检查：

- 实时 STT 目录内的 `models/<组织>/faster-whisper-<模型>/`。
- `HF_HUB_CACHE`，或 `HF_HOME/hub`，或默认 Hugging Face 缓存的完整 snapshot。

目录需要非空 `model.bin`、`config.json`、`tokenizer.json` 及 `vocabulary.*`。`.download`、分片及其他未完成的下载不会被加载。模型权重的完整性还需准备阶段核对，设置页的“已准备”仅表示必要文件存在。

本轮已用本机现有 `large-v3-turbo` 对合成语音验证本地加载、中文结果和时间戳。完整 `large-v3` 的新权重下载已按用户要求停止并延后，未进行该模型的质量验收。未开启真实设备录音，也未上传任何录音。

## 文件与恢复

每会话目录为 `data/recordings/<会话编号>/`，由现有 `data/` 规则排除在 Git 外：

| 文件 | 内容 |
| --- | --- |
| `manifest.json` | 会话起止、分轨、采样率、时段、缺包及转写状态 |
| `000000-mic.wav` 等 | 原生采样率、16 位 PCM 音频 |
| `realtime.jsonl` | 实时识别和决策事件，含相对时间 |
| `transcript.json` | 本地模型原文、时间戳、音频摘要、人工核对结果 |
| `local-asr.log` | 本地转写诊断，不写转写正文 |

音频通过受字节预算限制的队列交给单独写盘线程，单文件最多 60 秒或约 16 MB PCM。这是存储分片，不是问题分段规则；当前离线识别按这些片段逐个处理，片段边界处仍可能影响识别质量。音轨身份按采集通道设置确定，不做同一路混合声音的说话人分离。

原生 PCM 大于压缩录音：48 kHz 双声道每小时约 691 MB，16 kHz 单声道约 115 MB；两路累加。录音存在缺包或磁盘错误时显示缺口提示。旧进程中断后恢复 WAV 帧数并标记中断；损坏的录音清单单独报错，保留原件，不阻塞其他会话启动。

转写任务串行，逐片段保存。失败或服务退出后可继续，已完成的同模型、同计算配置、同音频 hash 片段复用结果；修改模型会重新转写。后台进程停止时终止本地推理子进程。

## 识别评估边界

离线结果保留模型原文，人工核对另存 `reviewed_text`，不覆盖原文。导出包含实时文本、离线文本、人工核对、时间和通道，可供后续错误归因与识别评测。

更大模型的结果仍可能错误，默认标为未核对，不能直接当作训练金标准。当前不自动学习、微调或用离线结果改写历史问题；后续需基于人工核对样本单独评估错字率、问题合并及误触发情况。
