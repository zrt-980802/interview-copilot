# Agent Prompt Injection 安全权限与治理

同义词：Agent Security、Prompt Injection、Jailbreak、Least Privilege、最小权限、Authorization、授权、Sandbox、沙箱、Data Exfiltration、数据外泄、Audit、审计。本文是通用技术资料，不证明候选人落地过这些控制。

## 一句话结论

Agent 安全的核心不是说服模型永远遵守 Prompt，而是假设模型会被误导，仍通过身份、最小权限、资源级授权、参数校验、沙箱、人工确认和审计把影响限制在可控范围。

## 从威胁建模开始

先列出需要保护的对象：用户数据、凭据、资金、代码、外部通信、系统可用性和审计记录。再标出输入源、模型、工具、存储、第三方服务和人工审批之间的信任边界。

威胁不只是 Prompt Injection。还包括越权读取、水平或垂直权限提升、路径穿越、SSRF、危险代码执行、资源耗尽、供应链能力替换、训练或记忆污染、密钥进入日志，以及借 Agent 向外发消息进行社会工程。

## Prompt Injection 与 Jailbreak

Jailbreak 通常是用户直接试图绕过模型政策；间接 Prompt Injection 来自网页、文档、邮件或工具返回，企图影响 Agent 动作。两者都不能只靠输入过滤彻底解决，因为自然语言与正常数据难以完美区分。

外部内容要有来源标签和独立数据通道；模型不能通过外部文本获得新权限；执行层根据用户原始意图、当前资源和风险再次校验。对高风险动作，展示实际对象和影响后单次确认。

### 如果 Prompt Injection 无法完全阻止怎么办

用纵深防御降低成功后的影响：不给模型凭据，限制工具与网络出口，做资源级授权，将读取与写入分开，对敏感数据和高风险动作加独立策略层，并用对抗测试与审计发现缺口。

## 身份、认证与授权

### 认证和授权有什么区别

认证回答请求者是谁，授权回答这个主体当前能对哪个具体资源执行什么动作。已登录不等于有权访问所有订单或文档；每次工具调用都要在服务端携带用户、租户、动作和资源重新授权。

认证回答“谁在请求”，授权回答“他能对哪个资源做什么”。Agent 不能仅因为调用者已登录就访问所有资源。每次工具执行使用当前用户、组织、任务和资源上下文做服务端授权。

优先使用短期、限范围、可撤销的凭据，不让 Agent 共享长期管理员密钥。委托授权需要记录原用户、委托方、范围和到期时间，不能在多 Agent 交接中悄悄扩权。

## 工具和数据的最小权限

为不同任务构建工具白名单，并从工具层进一步限制动作、资源和数量。例如“邮件工具”不应等于能以任意身份向任意收件人发送任意附件。

检索和 Memory 在查询时就要按租户、用户和资源 ACL 过滤。不能先召回越权内容，再希望模型不在答案中泄露。缓存键和向量索引也要包含同样的隔离维度。

## 沙箱、网络与代码执行

执行不可信代码时，使用独立身份和短生命周期环境，限制 CPU、内存、磁盘、时间、进程数、系统调用和文件根目录。默认无网络，如果必须访问，使用域名、协议、端口、重定向和私有网段策略。

容器是隔离手段之一，不是自动安全。还需要非特权用户、只读基础文件系统、最小挂载、无宿主凭据、镜像签名与漏洞管理，并假设沙箱存在逃逸可能。

## 数据、私隐和记忆治理

对输入、Trace、Memory、评测集和模型提供商传输分别定义数据分类、合法用途、保留期和删除路径。数据最小化优先于“全部记录以后再说”。

长期 Memory 写入需要来源、用户范围和准入规则。不将模型推断当用户事实，不将外部恶意指令存成持久政策，删除原数据时还要处理摘要、Embedding、缓存和评测副本。

## 人工确认与审计

确认必须是知情的：展示具体动作、对象、关键参数、不可逆影响和来源。旧确认不能被重用到对象或参数已改变的新动作。确认之后执行层仍重新检查权限和状态，防止检查与执行之间被替换。

审计记录需关联用户、Agent、模型、工具、资源、决策和结果，并防止普通执行者篡改。日志只保留调查必需内容，敏感参数做脱敏或哈希摘要。

## 常见失败场景

- 用“忽略恶意指令” Prompt 代替工具权限和执行校验。
- 共享管理员凭据放在 Context 或所有 Agent 的环境变量中。
- RAG 在召回后才做权限过滤，越权文本已进入模型。
- 用户确认了草稿，执行前参数又被模型修改。
- 日志保留完整 Prompt、密钥、个人数据和工具返回。
- 沙箱可访问云元数据端点或宿主挂载，导致凭据外泄。

## 生产实现检查表

建立威胁模型和信任边界；用户、Agent 和工具身份分离；资源级授权在服务端强制；工具和网络最小权限；凭据短期且不入 Context；高风险动作绑定具体确认；沙箱有资源、文件和网络限制；检索、Memory 和缓存保持租户隔离；日志脱敏且可审计；用对抗集验证工具确实未越权执行。

## 20 秒口述

我会假设模型可能被 Prompt Injection 误导，所以安全边界不放在 Prompt 里。用户和 Agent 分离身份，工具在服务端做资源级授权，凭据不进 Context，高风险动作绑定具体确认，代码和网络在受限沙箱中执行。

## 1 至 2 分钟展开

我会先列出数据、凭据、外部动作和系统可用性等资产，再画用户、模型、工具、存储和第三方之间的信任边界。外部文本永远是数据，不能扩展权限。每次工具调用都携带原用户和资源上下文，在服务端做授权。写操作再加参数校验、幂等和风险确认。代码执行默认无网络并限制资源。最后用攻击集检查的不只是模型回答，而是工具、数据和外部状态是否真的没有越界。

## 高频追问

### 怎样防止数据外泄

从数据流入手：召回前做 ACL，Context 最小化，工具返回脱敏，模型提供商按数据分类选择，网络出口限制目标，日志和缓存保持租户隔离，并对敏感内容的外发动作单独确认与审计。

### 有人工确认就安全吗

不是。确认可能被疲劳点击，或显示内容与实际执行不一致。应只在真正高风险节点确认，展示具体影响，将确认绑定到不可变的动作摘要，执行前重新授权，并保留独立审计。

## 系统设计练习

设计邮件 Agent：只读搜索与发送使用不同工具和权限；附件在隔离解析器中处理；邮件内容标记为不可信数据；发送前显示收件人、主题、附件和外发敏感数据；确认绑定内容哈希；执行时重新验证用户凭据；幂等键防重发；审计保留脱敏摘要。
