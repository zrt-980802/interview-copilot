# 资料库

目标是一份当前简历，加上面试时可供参考的项目资料、论文、技术文档和 GitHub Markdown。资料初始化后按问题检索，不将所有文件全文堆入每次请求，也不把参考资料自动当成本人经历。

## 上传与初始化

电脑工作区的资料库图标打开 `/files`。点击“批量上传”一次选择多份文件，清单中可继续添加、移除或修改本批资料类型，确认后点击“开始上传”。逐份显示已接收、已存在或失败；部分失败时“重试失败文件”只提交失败项，不重复提交成功文件。关闭清单回到资料详情及初始化状态。简历保持每次一份当前版本，选择简历类型后入口显示“上传简历”。

也可通过“导入 GitHub”粘贴具体的公开 Markdown 文件链接。文件各自保存，原文件名相同也不会覆盖；相同内容的重复上传返回已有条目，类型不被新上传请求悄悄改变。

正文初始化依次完成原文件保存、正文解析、按章节/行号分块和加入关键词索引。页面显示等待、解析、索引、就绪或失败；失败文件可单独重试。正文预览最多 16000 字，预览节选不等于索引只保留这些文字。

所有已上传文件的列表行右侧均提供垃圾桶按钮，详情也有“删除文件”，包括已就绪、处理中、失败、停用及已归档的资料。删除需确认，会永久移除条目、原件、正文、事实卡片、核对记录及对应检索缓存；取消确认保留文件。历史回答及已保存的来源摘录保留原快照，已经发给模型的内容无法收回。

解析失败时，文件列表直接显示失败原因和“重新解析”，详情也提供重试。重新解析使用已保存的原件，不必重新上传；归档的失败文件须先恢复才能重试。归档仍保留原件，永久删除无需先归档或停用。

正文就绪后，后台独立进行 AI 结构化分析和本地语义建库。概览优先显示标为“AI 摘要”的结果，尚未分析时显示开头节选。“已就绪”表示正文可以检索，“分析完成”和“语义索引已就绪”分别表示两条后台流程的状态；任一路失败都保留关键词检索。

参考资料每批最多 20 份，单文件最多 25 MB。支持 PDF、DOCX、Markdown、TXT、HTML 和常见代码/配置文本。PDF 限 250 页，提取正文最多 200 万字符；解析文本保留页码标记，扫描件不含可提取文字时提示先进行 OCR。HTML 只提取正文、标题及表格文字，跳过脚本和样式，不执行代码或请求外部资源。Word 读取正文与表格文字，不运行宏或解压外部路径；暂不支持旧 `.doc` 文件。文本尝试 UTF-8/BOM，其次 GB18030，无法识别时显示失败。

原文、解析文本和清单存于 `data/documents/`，该目录受现有 `data/` 忽略规则保护。已就绪文件在重启后使用保存的正文恢复检索索引；初始化中断的文件重新排队。原文件、启用状态、分类、名称和归档状态持久保存。

首次启用新版提取器时，已有 PDF/HTML 自动重新排队提取，原件和历史回答保持原快照。已有卡片按正文、类型和分析策略的指纹失效，避免新文本沿用旧行号。

## 事实与项目

文件详情的“事实与项目”显示按主体整理的角色、做法、技术、结果、指标及时间。每条记录保留连续引句、原始文本行号和来源；“原文”可读取预览范围以外的对应行，不只依赖前 16000 字。

- 资料陈述：候选人材料中直接陈述的内容，未作外部真实性认证。
- 仅供参考：普通资料、准备笔记、论文与岗位说明中的内容；上传论文不证明本人作者身份。
- 计划或预计、待确认：保留原文的不确定性，不改写为已完成成果。
- 存在冲突：同一主体、同一单值属性出现不同内容；不同学校的学习时间分别比较，毕业月份按年月归一后比较。
- 已确认、已排除：本人在界面作出的核对决定，可以撤销；重新分析保留未变化记录的核对结果。

提取器校验引句是否存在于原文、行号范围与数字是否得到引句支持。匹配不到的结果丢弃并显示数量。引句匹配是定位校验，不能证明模型对引句的释义或文档本身完全正确，仍需人工核对。资料中的指令不构成应用指令。

单次分析为简历/本人材料最多 6 个约 2500 字符窗口，论文最多 6 个约 11000 字符窗口，其他参考资料最多 3 个约 11000 字符窗口。超出时明确显示部分分析；全文仍参与原文检索。分析失败可在详情点击“分析资料”重试，已完成也可重新分析。

## 回答与检索

原文和卡片的中英文概念表示同时参与本地语义及 FTS5/BM25 检索，通过排名融合选择片段；给回答模型的证据保留原文引句与原始行号。资料标题参与排序，具体机制按正文概念筛选，不因错误专名命中另一份标题就删除正确候选；英文补充检索不会覆盖完整问题得到的更好评分。

个人经历问题优先组织有来源的本人卡片。一般技术题直接解释机制；项目方法题区分材料记载与通用方案。人工核对约束单独进入上下文，并完整保留；预算不足时拒绝请求，不截去核对约束后继续发送旧材料。关闭或归档资料会停止其后续卡片和语义召回。

模型知识不受资料清单限制。资料未覆盖或相关性低时，通用技术与设计问题照常由配置的模型回答，不为凑来源强行引用简历。特定文档的机制、实验条件以及个人角色和成绩仍需对应证据。语义匹配阈值只是召回启发式，不是事实正确性的概率。

AI 初始化会将分段正文发送给当前配置的回答 Provider，使用既有密钥、取消与备用通道；作答时按题发送相关片段、核对约束，个人经历题还包含当前简历，通用题省略整份简历。本地 BGE-M3 在 CPU 上生成语义向量，向量缓存在 `vectors.db`，卡片和核对决定存于 `knowledge.db`。不会训练或微调模型，不自动联网查证个人经历。

语义模型只加载本机已有缓存或显式配置的本地目录，不在服务启动时下载。缓存模型在后台预热，避免第一题承担加载成本；不可用时显示错误并使用关键词检索。可选依赖与开关见 `configuration.md`。

## 类型与使用范围

- 简历：每次上传一份，作为当前候选人背景。新简历成功初始化后切换生效，失败时保留原有可用简历；旧副本留在资料库中，不覆盖原文件。
- 本人项目资料：由用户明确选择的本人经历材料，作为 `candidate_material`。该分类本身不是内容真实性认证。
- 参考资料：默认类型，包括普通技术文件和 GitHub 导入，作为 `reference`，不能自动成为“我做过”的经历。
- 论文：作为 `paper`，不因上传行为推断本人作者身份或实验成果。
- 岗位说明：作为 `job_description` 的可检索资料；本阶段未增加岗位配置与资料分组管理。

启用开关控制该文件是否进入后续问题的检索；初始化完成前不能手动启用。关闭不会回收已经发送给模型的内容，也不改变历史答案的来源快照。归档会停用文件并移到归档视图，原文件保留；恢复后需手动启用。可以修改资料名称和类型、查看正文、下载原文件。

旧版简历、论文和材料仍通过兼容链路加载，在“原有资料”区域列出。当前新资料的开关不控制这些旧条目，旧原文件和缓存没有自动搬迁或删除；旧资料的统一迁移与范围管理仍需后续接入。原有简历可以显式重新选用。

## GitHub Markdown

支持 `https://github.com/<owner>/<repo>/blob/<ref>/<path>.md` 和对应的 `raw.githubusercontent.com` 链接，也支持 `.markdown`。保留规范化的 raw 链接作为来源，下载正文进入同一初始化流程；后续引用能携带此链接和行号，并保存到历史来源快照。

仅访问固定的 GitHub raw 主机，不跟随重定向、不发送模型 API key 或仓库 token；查询参数与 fragment 不保存。单份远程 Markdown 最多 5 MB，整体请求最多 30 秒，网络失败会提示重试。遵循进程已有的代理/证书环境配置。私有仓库、目录链接、整库克隆和自动跟踪更新暂不支持。文件内容改变后需重新导入，旧快照保持原样。

## 验证范围

文件清单与初始化状态、重启恢复、失败重试、启用范围、来源类型、下载、GitHub URL/重定向/大小边界、桌面与窄屏操作均有自动回归。真实导入公开 pgvector README 并验证本地索引和回答来源快照；模型传输仍为合成预览，不代表新的回答质量验收。

电脑管理入口仅在回环访问，资料库拒绝跨站请求。手机端不能访问资料库页面、文件 API 或下载原文件。手机仍可能看到回答正文中的必要摘录。
