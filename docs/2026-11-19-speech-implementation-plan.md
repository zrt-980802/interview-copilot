## 3. VOICE-00：可复现基线

任务：

1. 建立 `tests/fixtures/speech/` 合成事件时间轴与 `tests/regression/test_speech_replay.py`，区分采集时间、ASR 返回时间和 EOT 完成时间；使用虚拟时钟，避免测试靠长时间 sleep。
2. 增加 `scripts/evaluate_speech.py`：同一输入分别跑当前行为和新方案，输出触发时刻、草稿、题组、遗漏与误触发。仅有历史识别文本的记录标注为 text-only，不能当作真实 ASR ground truth。
3. 明确评测语料的正确文字、说话角色、属于哪道问题、可提交时间范围与是否无效输入。真实个人音频和标注保存在忽略目录，只将合成或许可明确的样例提交。
4. 保存当前配置、模型/代码版本和机器信息，记录冷启动与热运行结果。建立采集帧丢失、排队音频年龄和一次问答触发的关联。

退出条件：旧行为能复现长题中途触发；无模型、无录音的回放结果可重复；指标分母和排除样本明确。产出 `docs/evidence/speech-v2-baseline.md`，个人原始样本不进入 Git。

## 4. VOICE-01：结构化转写与兼容边界

涉及位置：新增 `src/interview_copilot/domain/speech.py`，扩展 `providers/stt.py`、`services/transcription.py`，兼容 `copilot/stt.py` 与 `legacy/transcription_adapter.py`。

任务：

1. 定义 AudioWindow、TranscriptUpdate、质量能力表和输入身份，区分 `input_epoch`、`revision` 与回答 generation；不破坏既有纯文字调用。
2. 按仓库现有补丁模式交付 `scripts/stt-structured-output.patch`，为当前本地服务增加可选结构化响应；text 默认行为保持兼容，音频时长和处理耗时拆开。补丁包含适用源码版本/哈希、应用与回退方法，不依赖隐藏手改。
3. 保留 Whisper 分段/可选词时间戳、avg_logprob、no_speech_prob、compression_ratio；缺失值为未知。解析对字段类型、时间范围、非有限数值和响应长度做边界验证。
4. 旧 adapter 继续仅供 legacy 模式；新链路输出 transcript_update，不能直接转换为 question。
5. 补充纯文本/结构化后端、未知质量、空结果、格式错误、超时和输入身份失效测试。

退出条件：正式 legacy 行为兼容，结构化结果能够追溯至音频范围；本地 STT 补丁可按记录应用/回退；版本可复现；新链路的任何识别输出都不能绕过后续协调器直接出题。

## 5. VOICE-02：连续采集、Silero 与窗口账本

涉及位置：新增 `audio/wasapi.py`、`audio/vad.py`、`audio/windows.py`、`services/transcript_ledger.py`，扩展既有 `TranscriptionService`。Windows PortAudio 管理初期复用 `copilot/audio.py` 的底层 helper，避免顺带重写设备管理。

任务：

1. 实现 AudioSource 的真实 WASAPI adapter，复用既有设备枚举、端点匹配和单线程 PortAudio 管理；验证耳机、扬声器及两路单独停止/换设备。
2. 接入可注入的 Silero/ONNX VAD，模型版本固定；按模型采样要求组帧，每路独立状态，保留 pre-roll。有状态重采样不因原始包长度变化产生不连续。
3. 将纯音频切块拆为 WindowScheduler：自然停顿优先、技术预算保底；技术切块不改变 draft 身份。保留音频区间、边界上下文与 gap。
4. 用 TranscriptLedger 维护范围覆盖、正文归属、同 span 修订和 finalized_through_sample；乱序最终稿不能越过未完成范围推进水位。
5. 建立共享有界识别调度，限制音频时长、任务数、音频年龄，明确两路公平性；过载/异常产生状态和缺口，不能直接丢任务后触发回答。

退出条件：55/120 秒连续音频跨窗不丢前提、不重复边界词；改变窗口预算得到相同核心转写；非人声和轻声有独立评测；停止/换会话后晚到结果无效；采集独立于网页。此阶段不接自动回答。

## 6. VOICE-03：Smart Turn 与唯一提交入口

涉及位置：新增 `providers/turn_detection.py`、`services/speech_turns.py`，复用 `services/question_flow.py`、`services/interview.py` 的现有能力。

任务：

1. 定义可注入的 TurnDetector 协议与 Smart Turn 本地实现，固定匹配的代码、权重与校验值；16kHz、最近 8 秒、补齐规则严格按模型约定。
2. 实现来源活动和问题构建两个状态机。语音恢复使旧 EOT 失效，尾部未识别区间必须先 flush，EOT 为真也必须等待转写连续覆盖。
3. 实现 accept_question / wait / context_only / reject / needs_review 及原因码。沿用保守背景线索，不按个人材料命中率过滤问题；关键数字和否定存在歧义则待确认。
4. 实现提交幂等及同题补充，协调器只发正式 commit/revise，不创建回答任务。桥接由下一阶段完成。补充事件簇稳定后一次修订，关联不确定时等待处理。
5. 模型不可用或超时显式降级；最大等待仅进入 needs_review。禁止“已经等到上限，所以自动回答”的分支。

退出条件：下面验收矩阵的确定性测试全部通过；无题目提交可绕过覆盖水位；模型异步判断不会跨越 epoch 或新的讲话活动；无额外逐段问答 LLM 请求。

## 7. VOICE-04：正式接线、电脑草稿和配对兼容

涉及位置：`server.py`、`legacy/transcription_adapter.py`、配置加载/启动器、`static/js/` 与工作区界面、history 和 mobile 投影测试。

任务：

1. 增加一个 `speech.mode=legacy/shadow/active` 入口。移除旧 v2 标记作为独立开关的歧义；冲突配置有明确升级错误。兼容 legacy 现有启动脚本和后台运行方式。
2. shadow 通过有界 tap 共享一次采集，不重复打开设备；默认回放/假识别比较，真实双推理只在限制负载后启用。shadow 结果不写正式问题、本人上下文或回答。
3. active 使用新流水线；QuestionCommit 才调用现有 `_start_question`，QuestionRevised 使用现有同题修订与取消；原 QuestionMerger 仅在 legacy 模式持有自动输入。
4. 电脑显示可编辑草稿和输入状态，提供提交/放弃。手动提问与草稿显式分离，不能重复提交。同步新增状态快照，刷新不丢掉正在等待的草稿。
5. 手机维持正式问题/回答投影，不接收原始转写；连续新对话、模式切换、设备重建、重连都保持已配对凭据和原到期时间。
6. 复用历史事件表保存决策/修订及关联；任何新字段为追加兼容。验证旧问题、旧答案和原510条 turns 不改写。

退出条件：真实 HTTP/SSE 与浏览器回归覆盖电脑和手机；后台关闭网页仍运行；两条路径恰好只有一条能触发正式成题；在暂停采集后可切回 legacy，历史与配对不受影响。

## 8. VOICE-05：真实语音验证与发布

任务：

1. 在用户主动提供/开启的样例上验证真实耳机回环、本人麦克风、轻声、键盘/提示音、咳嗽及串音，记录实际播放端点和模型版本。
2. 同一批样例进行新旧方案配对比较，单独报告中文、英语术语、数字、否定、长题和停顿；区分采集错误、ASR 错误、端点错误和成题错误。
3. 目标为误触发与抢答各减少至少 50%，有效问题召回下降不超过2个百分点。每类报告样本数和绝对错误数，小样本结论标为初步；持续长题的“讲话中不提交”和旧身份拒收必须为零违规。
4. 报告说完到正式提交、说完到首字的 P50/P95；明确测试机器和冷/热启动。优先验证原有本地 Whisper 热运行下提交 P95 不超过3秒的可行性；这是待验证目标，不为达标而放松完整性屏障。
5. 任一关键门禁失败，保留 legacy 默认和手动提问，不宣称全部验收。通过后将 active 设为默认并记录灰度范围、历史备份、回退步骤和遗留项。

退出条件：新语音链路具备真实样例证据，可重复安装与启动；模型故障、负载异常和回退过程已验证；不只是合成转写测试通过。

## 9. VOICE-06：可选中文识别后端对照

在统一 TranscriptUpdate 协议下新增 FunASR 两遍 adapter。online 稿只更新草稿，offline 最终稿修订同一 span；保持同一 draft 和提交屏障。SenseVoice 可作为句末复核候选，事件标签保留到质量层，不把非流式模型伪装为原生流式。

同样本比较现有 Whisper、Paraformer 两遍和必要时 SenseVoice：CER、术语/数字/否定准确率、错误修订、P95 延迟、内存/显存、Windows 部署与恢复。模型权重许可单独核对。只有结果支持收益时才改默认，不能因为换了引擎就跳过端点、质量或完整性检查。

## 10. 必须覆盖的验收矩阵

| 编号 | 输入/故障 | 预期不变量 | 最早阶段 |
| --- | --- | --- | --- |
| LONG-01 | 55秒连续讲题，跨18秒位置 | 讲话中零自动提交；结束后一道题，保留全部条件 | 02/03 |
| LONG-02 | 120秒、多个技术窗口 | 不因窗口大小多出题；全文/范围不被8秒EOT窗口截断 | 02/03 |
| WINDOW-01 | 同录音用不同处理窗口 | 核心文字与题目数量一致，边界误差单列 | 02/03 |
| PAUSE-01 | 未完题中停2/4/6秒，EOT给未完成 | 持续等待，后半题并入同一draft | 03 |
| PAUSE-02 | 安静后EOT请求发出，又继续说 | 旧EOT为真也不得提交 | 03 |
| BARRIER-01 | EOT已完成，最后一个ASR请求仍阻塞 | 待识别状态；最后稿到齐才允许提交 | 03 |
| ORDER-01 | 第3窗先于第2窗返回，含重复/旧版本 | 不跳水位、不乱拼、不重复提交 | 02/03 |
| BOUNDARY-01 | 技术词/否定跨窗，正常重复词 | 保留语义，不能靠字符串去重删词 | 02 |
| REVISION-01 | online后offline纠错；已提交后明确补充 | 提交前同span替换；提交后同turn修订，旧generation取消 | 03/04 |
| NOISE-01 | 静音、键盘、咳嗽、提示音及夹杂真问题 | 无效片段不触发；真实问题不整句丢弃 | 02/03/05 |
| CONTEXT-01 | 背景说明、本人回答、没命中资料的新题 | 前两者只作上下文；有效新题正常回答 | 03/04 |
| GAP-01 | 丢帧、队列溢出、ASR失败/过时 | 显式缺口/降级，不能把部分问题当完整 | 02/03 |
| LIFE-01 | 换设备、新会话、停止时仍有请求 | 旧epoch结果不落当前draft，停止不等于提交 | 02/04 |
| PHONE-01 | 连续新对话、模式切换、重连 | 配对不撤销，旧题清除，只见正式内容 | 04 |
| SHADOW-01 | 主链路与shadow同时收到同音频 | 采集仅一次、只有主路径触发问答/本人上下文 | 04 |
| MANUAL-01 | 编辑/手动提交时自动结果晚到 | 草稿归属明确，不重复新建题目 | 04 |
| DEGRADED-01 | EOT缺失、质量字段缺失、等待超限 | 不伪造置信；显式保守降级或待确认 | 01/03 |

PAUSE-01 的自动测试控制 EOT 输出，证明状态机正确；真实模型能否准确给出未完成判断必须由05的真实音频验证，不能混用两者结论。

## 11. 发布与回退检查

1. 保存配置版本、模型校验值、历史备份及当前健康状态；暂停两路采集，确认无活动回答。
2. 在隔离端口验证 HTTP/SSE、配置错误、未授权手机访问、草稿恢复和配对保留。
3. 正式启用 active 后验证真实服务装配的是新输入路径，不能只依据模块单测或配置值断言。
4. 回退时暂停输入、切 mode、失效两路 input_epoch，再恢复所选设备；不更换当前会话、不清历史、不调用 mobile revoke_all。
5. 发布报告记录新旧路径、测试命令与结果、真实样本范围、延迟、遗漏和回退结果。模型/设备原因未完成的项目必须明确列出。

本地 STT 补丁部署需要重启8760服务时单独安排在空闲期；主服务进程若也重启，手机仍需重新配对。不能把“进程内切换保持配对”说成“任意进程重启都保持配对”。

## 12. 下一步的具体起点

首先实施 VOICE-00：建立55秒跨窗、中途停顿、识别晚到三个确定性回放用例，并保存当前基线。随后实施 VOICE-01 的结构化转写。最先验收的是“部分文字不会提前提交”的证据链，而非单独把18秒参数改大。
